## 概述

期末结转是会计月末结账的核心流程，包含结账前检查、损益结转、折旧结转、增值税结转及结账/反结账操作。

**实现现状**：

| 功能模块 | 状态 | 说明 |
|----------|------|------|
| 结账前检查（checkBeforeClose） | ✅ 完整实现 | 4 项检查：期间状态、未记账凭证、试算平衡、红冲凭证 |
| 结账（closePeriod） | ✅ 完整实现 | 修改期间状态为 CLOSED |
| 反结账（reopenPeriod） | ✅ 完整实现 | 恢复期间状态为 OPEN |
| 损益结转（generateProfitCarryOver） | ⚠️ 占位实现 | 生成汇总 DRAFT 凭证，未区分收入/费用类，未结转至本年利润科目 |
| 折旧结转 | ❌ 缺失 | 未实现 |
| 增值税结转 | ❌ 缺失 | 未实现 |
| 结转模板配置 | ❌ 缺失 | 未实现 |
| 结账日志（listCloseLog） | ❌ 占位 | 返回空列表 |

## 1. 输入契约

### 1.1 结账前检查

```
GET /api/v1/period-close/check?period={periodCode}
```

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| period | String | 是 | 会计期间编码，格式 YYYYMM |

**前置条件**：
- 期间在 `t_period` 表中存在（`periodCode` 匹配）
- 期间状态非 `CLOSED`（否则抛出 400）
- 期间状态非 `LOCKED`（否则抛出 400）

### 1.2 执行结账

```
POST /api/v1/period-close/close?period={periodCode}
```

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| period | String | 是 | 会计期间编码，格式 YYYYMM |

**前置条件**：
- 通过 `checkBeforeClose` 检查（passed = true）
- 当前用户已登录（通过 `SecurityUtils.getCurrentUserId()` 获取）

### 1.3 反结账

```
POST /api/v1/period-close/reopen?period={periodCode}
```

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| period | String | 是 | 会计期间编码，格式 YYYYMM |

**前置条件**：
- 期间在 `t_period` 表中存在
- 期间状态为 `CLOSED`（否则抛出 400）

### 1.4 生成损益结转凭证

```
POST /api/v1/period-close/profit-carryover?period={periodCode}
```

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| period | String | 是 | 会计期间编码，格式 YYYYMM |

**前置条件**：
- 期间在 `t_period` 表中存在
- 当前用户已登录

### 1.5 查询结账日志

```
GET /api/v1/period-close/log?period={periodCode}
```

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| period | String | 是 | 会计期间编码，格式 YYYYMM |

## 2. 输出契约

### 2.1 结账前检查响应

```json
{
  "passed": true,
  "issues": [],
  "trialBalance": {
    "period": "202607",
    "beginBalanced": true,
    "movementBalanced": true,
    "endBalanced": true,
    "totalBeginDebit": 100000.00,
    "totalBeginCredit": 100000.00,
    "totalDebitTotal": 50000.00,
    "totalCreditTotal": 50000.00,
    "totalEndDebit": 150000.00,
    "totalEndCredit": 150000.00,
    "balanced": true
  }
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| passed | boolean | 检查是否通过 |
| issues | String[] | 未通过项列表（passed=false 时填充） |
| trialBalance | Object | 试算平衡表，详见 SubjectBalanceService.checkTrialBalance |

**检查项明细**（4 项）：

| 检查项 | 条件 | 失败时 issues 内容 |
|--------|------|-------------------|
| 期间未结账 | periodEntity.status != "closed" | 抛异常（400），不进入 issues |
| 期间未锁定 | periodEntity.status != "locked" | 抛异常（400），不进入 issues |
| 无未记账凭证 | count of voucher where period=period AND status!="POSTED" AND deleted=0 == 0 | "存在 N 张未记账凭证" |
| 试算平衡 | checkTrialBalance(period).balanced == true | "试算不平衡, 借方发生 X / 贷方发生 Y" |
| 无红冲草稿凭证 | count of voucher where period=period AND reversedFrom IS NOT NULL AND status="DRAFT" AND deleted=0 == 0 | "存在 N 张草稿状态的红冲凭证未提交" |

### 2.2 结账响应

```json
{
  "code": 200,
  "message": "ok"
}
```

无业务数据体。成功时期间状态变更为 `closed`。

### 2.3 反结账响应

```json
{
  "code": 200,
  "message": "ok"
}
```

无业务数据体。成功时期间状态恢复为 `OPEN`。

### 2.4 损益结转凭证响应

```json
{
  "code": 200,
  "message": "ok",
  "data": 42
}
```

`data` 为生成的凭证 ID（`VoucherEntity.id`）。生成的凭证：
- 状态：`DRAFT`（草稿）
- 来源：`GENERATED`
- 摘要："自动结转损益: {period}"
- 凭证号格式："CLOSE-{period}-{流水号}"
- 分录：仅生成一条代表性分录（占位实现），摘要为"损益结转占位, 请手工调整到本年利润科目"

### 2.5 结账日志响应

```json
{
  "code": 200,
  "message": "ok",
  "data": []
}
```

当前实现返回空列表。

## 3. 状态流转

### 3.1 期间状态机

```
                    closePeriod(检查通过)
 OPEN ──────────────────────────────────────> CLOSED
  ^                                              |
  |                                              |
  └────── reopenPeriod(状态为CLOSED) ───────────────┘
```

**期间状态定义**（PeriodEntity.status）：

| 状态值 | 说明 |
|--------|------|
| OPEN | 开启，可录入凭证、可结账 |
| CLOSED | 已结账，不可修改，不可再次结账 |
| LOCKED | 已锁定，不可结账（抛出 400） |

### 3.2 凭证状态定义

自动结转凭证遵循标准凭证状态机：

```
DRAFT ──提交──> SUBMITTED ──审核──> AUDITED ──记账──> POSTED
```

当前损益结转实现仅生成 `DRAFT` 状态凭证，后续提审/审核/记账由用户手工完成。

### 3.3 负向断言（禁止的跳转）

| 源状态 | 目标状态 | 操作 | 禁止原因 |
|--------|----------|------|----------|
| OPEN | CLOSED | closePeriod | 结账前检查未通过时禁止 |
| OPEN | CLOSED | closePeriod | 期间状态为 LOCKED 时禁止 |
| CLOSED | CLOSED | closePeriod | 已结账期间禁止重复结账 |
| CLOSED | CLOSED | reopenPeriod | 反结账仅恢复为 OPEN，不重复关闭 |
| OPEN | OPEN | reopenPeriod | 仅 CLOSED 状态可反结账 |

## 4. 异常处理

### 4.1 异常码定义

| 场景 | HTTP 状态码 | 错误信息 | 触发条件 |
|------|-------------|----------|----------|
| 期间不存在 | 404 | "会计期间不存在: {period}" | `findPeriod()` 未查到记录 |
| 期间已结账 | 400 | "期间已结账" | `checkBeforeClose` 检测到 status=CLOSED |
| 期间已锁定 | 400 | "期间已锁定, 不能结账" | `checkBeforeClose` 检测到 status=LOCKED |
| 结账检查未通过 | 400 | "结账检查未通过: {issues列表}" | `closePeriod` 调用 checkBeforeClose 返回 passed=false |
| 期间未结账 | 400 | "仅已结账期间可反结账" | `reopenPeriod` 检测到 status != CLOSED |
| 期间格式错误 | 400 | "会计期间格式错误, 应为 YYYYMM" | period 参数长度不为 6 |

### 4.2 降级策略

| 异常场景 | 降级行为 |
|----------|----------|
| 试算不平衡 | 不阻塞结账前检查，将问题加入 issues 列表，由调用方决定是否继续 |
| 损益结转失败 | 事务回滚，不生成凭证，不修改期间状态 |
| 结账操作失败 | 事务回滚，期间状态维持不变 |

### 4.3 事务边界

- `closePeriod()` — 标注 `@Transactional(rollbackFor = Exception.class)`，包含检查 + 改状态
- `reopenPeriod()` — 标注 `@Transactional(rollbackFor = Exception.class)`，包含检查 + 恢复状态
- `generateProfitCarryOver()` — 未标注事务注解（依赖 MyBatis-Plus 默认行为）

## 验收标准（BDD）

### 场景 1：结账前检查 — 全部通过

- **Given** 会计期间 202607 状态为 OPEN，所有凭证已记账，试算平衡，无红冲草稿
- **When** 调用 `GET /api/v1/period-close/check?period=202607`
- **Then** 返回 `{ "passed": true, "issues": [] }`
- **And** `trialBalance.balanced` 为 true

### 场景 2：结账前检查 — 存在未记账凭证

- **Given** 会计期间 202607 下存在 3 张状态为 DRAFT 的凭证
- **When** 调用 `GET /api/v1/period-close/check?period=202607`
- **Then** 返回 `{ "passed": false, "issues": ["存在 3 张未记账凭证"] }`

### 场景 3：结账前检查 — 试算不平衡

- **Given** 会计期间 202607 的借方发生总额与贷方发生总额不相等
- **When** 调用 `GET /api/v1/period-close/check?period=202607`
- **Then** 返回 `{ "passed": false }`
- **And** `issues` 包含 "试算不平衡" 相关描述

### 场景 4：结账前检查 — 已结账期间拒绝

- **Given** 会计期间 202607 状态为 CLOSED
- **When** 调用 `GET /api/v1/period-close/check?period=202607`
- **Then** 抛出 BusinessException(400, "期间已结账")
- **And** 期间状态不变

### 场景 5：结账前检查 — 已锁定期间拒绝

- **Given** 会计期间 202607 状态为 LOCKED
- **When** 调用 `GET /api/v1/period-close/check?period=202607`
- **Then** 抛出 BusinessException(400, "期间已锁定, 不能结账")

### 场景 6：执行结账 — 成功

- **Given** 会计期间 202607 状态为 OPEN
- **When** 调用 `POST /api/v1/period-close/close?period=202607`
- **Then** 返回 HTTP 200
- **And** `t_period` 表中对应记录的 status 变更为 "closed"

### 场景 7：执行结账 — 检查不通过时拒绝

- **Given** 会计期间 202607 存在未记账凭证
- **When** 调用 `POST /api/v1/period-close/close?period=202607`
- **Then** 抛出 BusinessException(400)
- **And** 期间状态维持 OPEN，事务回滚

### 场景 8：反结账 — 成功

- **Given** 会计期间 202607 状态为 CLOSED
- **When** 调用 `POST /api/v1/period-close/reopen?period=202607`
- **Then** 返回 HTTP 200
- **And** `t_period` 表中对应记录的 status 变更为 "open"

### 场景 9：反结账 — 未结账期间拒绝

- **Given** 会计期间 202607 状态为 OPEN
- **When** 调用 `POST /api/v1/period-close/reopen?period=202607`
- **Then** 抛出 BusinessException(400, "仅已结账期间可反结账")

### 场景 10：损益结转 — 生成凭证（当前占位实现）

- **Given** 会计期间 202607 下存在已记账凭证，包含损益类科目发生额
- **When** 调用 `POST /api/v1/period-close/profit-carryover?period=202607`
- **Then** 返回生成的凭证 ID（Long）
- **And** `t_voucher` 表新增一条记录，status="DRAFT", source="GENERATED", summary="自动结转损益: 202607"
- **And** `t_voucher_entry` 表新增一条分录，summary="损益结转占位, 请手工调整到本年利润科目"

### 场景 11：损益结转 — 空期间

- **Given** 会计期间 202607 下无任何已记账凭证
- **When** 调用 `POST /api/v1/period-close/profit-carryover?period=202607`
- **Then** 返回生成的凭证 ID
- **And** 凭证总金额为 0.00

### 场景 12：期间不存在

- **Given** 会计期间 999999 在 `t_period` 表中不存在
- **When** 调用任一接口（check/close/reopen/profit-carryover）且 period=999999
- **Then** 抛出 BusinessException(404, "会计期间不存在: 999999")
