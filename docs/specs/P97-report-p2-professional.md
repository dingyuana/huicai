## 0. 背景与现状差距（代码 trace，全部已核验）

本 SPEC 含 4 个相互独立的子特性，各自成段。

### 0.1 利润表（REQ-099）：法定行缺失 + 期间费用死数

- `IncomeStatementView.vue` L89-95 硬编码 7 行结构：营业收入 / 营业成本 / 毛利 / **减:期间费用** / 营业利润 / 减:其他支出 / 利润总额；L92「减:期间费用」取 `expense` 单字段、`fixed: true`（L87 注释：法定报表结构必须完整呈现，零值不隐藏）
- `ReportDataMapper.java` `incomeStatementData`（L35-52）：
  - `expense` = `6601% OR 6602% OR 6603%` **三科目捆绑求和**（不可展开的死数）
  - `other_expense` = `6604~6617 + 6701 + 6711` 段捆绑
- 缺口：无 **研发费用 / 其他收益 / 营业外收支 / 所得税费用** 法定行；期间费用无法下钻到管理/销售/财务三费
- ⚠️ **口径拍板项**：新增行的科目映射实现前必须与 `t_subject` 实际科目表对证，**本 SPEC 不臆造科目号**；按账套准则（小企业会计准则 vs 企业会计准则）决定法定行全量展示或缺省隐藏

### 0.2 科目余额表（REQ-097）：平铺无层级、无辅助核算

- `SubjectBalanceView.vue` L39 已输出 `level` 列（数据来自 `t_subject.level`），但**全表平铺、无树状折叠**
- 无辅助核算维度展开：`assist_json`（JSONB）字段未在余额表呈现（Entity 侧 String→JSONB 必须带 `JsonbTypeHandler`——陷阱 4.4-6）
- 到凭证的穿透已存在（P89-C，L130），**本批不重复**

### 0.3 报表重分类（REQ-098）：完全缺失

- `ReportServiceImpl.balanceSheet()` 按科目首字符 switch 归类（L64-127），**无**「预付账款贷方余额→应付账款借方」「应收账款贷方→预收账款」等准则重分类
- 重分类是**列报层**动作：只影响报表呈现，不改账、不出凭证

### 0.4 异常诊断（REQ-100）：无任何提示

- 三表与驾驶舱无「期间 0 收入但有费用」「连续 N 期无收入」「期末现金骤降」类诊断
- 关联 REQ-2026-037（异常指标告警，SPC-018-P3 ⏳ 规划中）——本批做报表页内的轻量规则黄条，AI/规则输出**只展示不处理**（铁律 #1/#2）

## 1. 输入契约

### REQ-097 树状与辅助核算
- 入参不变（period）；树结构由 `t_subject.parent_id/level` 前端组树（草案：也可后端返回树，实现时定）
- 辅助核算展开维度：客户/供应商/项目/部门（草案：query 参数 `auxType`），数据源 `assist_json`

### REQ-098 重分类
- 开关参数（草案）：`reclass=true/false`，默认关（=与现状完全一致）
- 规则集（草案）：预付贷方→应付借方、应收贷方→预收借方等，规则可配置

### REQ-099 利润表法定行
- 口径参数（草案）：账套准则标识（小企业/企业），决定法定行显隐
- 展开动作：前端本地展开（费用三明细已在 SQL 分列，草案新增 `mgmt_expense/selling_expense/finance_expense` 字段）

### REQ-100 异常诊断
- 只读规则集（草案，阈值实现时定）：期间收入=0 且费用>0；连续 N 期收入=0；期末现金较上期降幅>50%；往来余额超期
- 无用户输入；黄条可关闭（仅本次会话）

## 2. 输出契约

- REQ-097：树状行 + 不变量「展开/收起前后合计守恒」；辅助核算明细行加总 == 所属科目合计
- REQ-098：重分类开关开 → 列报变而**凭证数、科目余额、损益完全不变**；开关状态显示在报表抬头；关 → 三表与现状 diff == 0
- REQ-099：法定行结构（按准则显隐）；展开时 `管理+销售+财务 == 减:期间费用` 父行；本年累计列与本期列同构
- REQ-100：黄色建议条数组（规则 id + 文案 + 触发值），**无任何写操作**
- 全部错误响应用全局 BusinessException 错误码体系（不新造平行体系）

## 3. 状态流转与副作用

- 四个子特性全部**只读**：无状态机
- 副作用声明：`DB_READ ONLY → t_subject / t_voucher_entry / t_voucher / t_subject_balance → 聚合与组树`
- 负向断言：
  - 重分类**禁止**生成凭证或修改任何科目余额（列报 ≠ 记账）
  - 诊断/建议**禁止**写任何业务表、禁止自动处理（铁律 #1/#2）
  - 逻辑删除约束：所有查询带 `deleted=0`（#12）

## 4. 异常处理

| 场景 | 处理 | 级别 |
|---|---|---|
| parent_id 指向已删除科目 | 子节点提升为根节点，不丢行（P92B-BD3 精神：未分类不得静默丢弃） | WARN |
| assist_json 解析失败 | 该单元格显示原值占位 + 日志，不 500 | ERROR（日志） |
| 重分类后借贷两侧互相抵消 | 按净额列报，双侧都不显示 0 行 | INFO |
| 法定行科目在科目表不存在 | 该行 0 值按准则显隐规则处理 | INFO |
| 诊断规则计算异常 | 跳过该规则并降级（黄条少一条），不影响报表主体 | ERROR（日志） |

事务：无写路径，不涉及铁律 #11；若实现中任何环节要写库 → **直接 reject**，回本 SPEC 重审。

## 验收标准（BDD）

### 场景 1：期间费用展开守恒（REQ-099）
- **Given** 利润表已加载，期间费用父行有值
- **When** 点击「减:期间费用」展开
- **Then** 管理费用 + 销售费用 + 财务费用 == 父行金额（容差 0.01）
- **And** 负向断言：展开不改变毛利/营业利润等其他行数值

### 场景 2：法定行按准则显隐（REQ-099）
- **Given** 小企业准则账套
- **When** 打开利润表
- **Then** 缺省法定行按拍板规则隐藏/置零；企业准则账套全量展示
- **And** 负向断言：任何准则下 `收入−成本−费用` 勾稽不被新增行破坏

### 场景 3：树状展开合计守恒（REQ-097）
- **Given** 含多级科目的余额表
- **When** 展开/收起父科目
- **Then** 任一状态下表尾合计与展开前 diff == 0
- **And** 负向断言：不出现父子重复计数

### 场景 4：辅助核算展开（REQ-097）
- **Given** 某往来科目启用了客户辅助核算
- **When** 展开该行
- **Then** 各客户明细加总 == 该科目合计（容差 0.01）

### 场景 5：重分类只改列报（REQ-098）
- **Given** 预付账款出现贷方余额
- **When** 开启重分类开关
- **Then** 该净额出现在应付（借方）列报中，报表抬头显示开关状态
- **And** 负向断言：凭证数不变、科目余额不变、**无新凭证生成**

### 场景 6：关闭重分类零差异（REQ-098）
- **Given** 关闭重分类开关
- **When** 对比本批前后三表
- **Then** 全字段 diff == 0（现状完全回归）

### 场景 7：零收入诊断只读（REQ-100）
- **Given** 某期间收入 = 0 且费用 > 0
- **When** 打开利润表
- **Then** 出现黄色诊断建议条（含规则文案与金额）
- **And** 负向断言：全程无任何表写入、无状态变更、无自动处理

**测试约束**：每场景一个 `@Test`；守恒类断言全部用 BigDecimal 容差比较（金额精度铁律 #7，禁 double/float）。

| 竞品 | 树状余额表/辅助核算 | 报表重分类 | 利润表法定行/费用展开 | 诊断 |
