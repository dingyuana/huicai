> **版本**：1.1

## 概述

支持代账机构多账套场景，实现租户级数据隔离，确保跨租户操作绝对拦截。

**当前状态**：项目为单租户架构，部分 Entity 有 `tenantId` 字段但硬编码为 `1L`。已有组织级数据隔离（`DataPermissionInterceptor`），但不是租户级隔离。

**已有代码基础**：
- `DataPermissionInterceptor`（MyBatis-Plus InnerInterceptor）：按角色 data_scope 注入 SQL 过滤条件
- 11 个 Entity 含 `tenantId` 字段（AiFeedbackLog/Prepayment/ReconciliationLog 等）
- `ClassificationRuleServiceImpl.seedForNewTenant(tenantId)` 已有按租户初始化种子数据的逻辑
- 硬编码 `tenantId=1L` 在 `AutoGenerationService` 和 `ClassificationRuleServiceImpl` 中

**缺失**：
- 无租户上下文传递机制（无 TenantContextHolder）
- 无跨租户操作拦截
- 大部分核心 Entity（Voucher/BusinessDoc/Invoice）无 tenantId 字段
- DB 表无 tenant_id 列（t_voucher/t_business_doc/t_output_invoice 等）

## 1. 输入契约

### 1.1 租户上下文

| 参数 | 类型 | 约束 | 说明 |
|------|------|------|------|
| tenantId | Long | 非空，从 JWT Token 解析 | 租户唯一标识 |
| userId | Long | 非空，从 JWT Token 解析 | 操作用户 |
| dataScope | String | 枚举：ALL/DEPT/DEPT_AND_CHILD/SELF/CUSTOM | 数据权限范围（已有） |

### 1.2 前置条件

- 用户已通过 JWT 认证（S-02）
- JWT Token 中包含 tenantId claim
- 目标实体所属表已添加 tenant_id 列

---

## 2. 输出契约

### 2.1 数据隔离效果

所有查询 SQL 自动注入 `WHERE tenant_id = :currentTenantId`，除非角色 data_scope = ALL。

### 2.2 跨租户拦截响应

```json
{
  "code": 20003,
  "message": "禁止跨租户操作",
  "data": null,
  "traceId": "uuid"
}
```

### 2.3 新租户初始化

调用 `seedForNewTenant(tenantId)` 后返回初始化的数据条数（分类规则、科目模板等）。

---

## 3. 状态流转

### 3.1 租户状态机

```
PENDING -> ACTIVE -> SUSPENDED -> TERMINATED
```

| 状态 | 说明 | 可转换到 |
|------|------|---------|
| PENDING | 创建未激活 | ACTIVE |
| ACTIVE | 正常使用 | SUSPENDED |
| SUSPENDED | 暂停（欠费等） | ACTIVE, TERMINATED |
| TERMINATED | 终止（数据保留） | （终态） |

### 3.2 负向断言

- PENDING 状态的租户不能执行业务操作（只能管理租户信息）
- SUSPENDED 状态的租户不能创建新数据（只能查看）
- TERMINATED 状态的租户不能执行任何写操作
- 不能通过修改 tenantId 参数访问其他租户数据

### 3.3 副作用

- 租户创建时：自动初始化分类规则（已有 `seedForNewTenant`）、科目模板、默认角色
- 租户终止时：数据保留不删除，标记 terminated_at

---

## 4. 异常处理

| 异常场景 | 错误码 | 降级策略 |
|---------|--------|---------|
| 租户上下文缺失 | 20004 | 拦截请求，要求重新登录 |
| 跨租户越权访问 | 20003 | 拦截操作，记录审计日志 |
| 租户已禁用 | 20005 | 返回提示，引导联系管理员 |
| 租户不存在 | 20007 | 拦截请求，记录异常 |

## 验收标准（BDD）

### 场景 1：单租户内正常查询
- **Given** 租户 A 的用户已登录，JWT Token 含 tenantId=A
- **When** 查询凭证列表
- **Then** 返回租户 A 的凭证数据
- **And** SQL 中自动包含 `WHERE tenant_id = A`
- **And** 不返回租户 B 的任何数据

### 场景 2：跨租户访问被拦截
- **Given** 租户 A 的用户已登录
- **When** 尝试通过 API 参数 `tenantId=B` 查询租户 B 的数据
- **Then** 返回错误码 20003「禁止跨租户操作」
- **And** 记录审计日志（用户/时间/目标租户/操作类型）
- **And** 不返回任何数据

### 场景 3：新租户初始化
- **Given** 管理员创建新租户 C
- **When** 调用 `seedForNewTenant(C)`
- **Then** 租户 C 的分类规则、科目模板被初始化
- **And** 初始化数据的 tenantId 全部为 C
- **And** 不影响其他租户的数据

### 场景 4：已禁用租户拦截
- **Given** 租户 D 状态为 SUSPENDED
- **When** 租户 D 的用户尝试创建新凭证
- **Then** 返回错误码 20005「租户已禁用」
- **And** 不创建任何数据

### 场景 5：tenantId 篡改检测
- **Given** 租户 A 的用户提交凭证，请求体中 tenantId=A
- **When** 请求到达 Service 层
- **Then** 系统以 JWT Token 中的 tenantId 为准，忽略请求体中的 tenantId
- **And** 如果两者不一致，记录审计日志

## 迁移路径（单租户 -> 多租户）

### 阶段 1：基础设施（不影响现有功能）
1. 新增 `TenantContextHolder`（ThreadLocal 存储当前租户 ID）
2. JWT Token 新增 tenantId claim
3. `DataPermissionInterceptor` 扩展：在现有 dept/created_by 过滤之上，增加 tenant_id 过滤

### 阶段 2：核心表添加 tenant_id
4. 核心业务表添加 `tenant_id BIGINT NOT NULL DEFAULT 1` 列（Flyway migration）
5. 现有数据全部设为 tenant_id=1（默认租户）
6. Entity 添加 tenantId 字段 + `@TableField(fill = FieldFill.INSERT)` 自动填充

### 阶段 3：租户管理
7. 新增租户 CRUD API
8. 新增租户状态机
9. 移除所有硬编码 `tenantId=1L`
