## 一、背景：为什么"反复不平衡"

`/report/balance-sheet` 不平衡不是单次数据错误，而是**三层问题叠加**，历史上只修过中间一层的表象（commit 58a82fe 改负债权益符号、90b28cd 改损益结转方向），根因未除。

### 根因 A：报表取数遗漏整类科目，破坏会计恒等式（结构性，必现）

`ReportServiceImpl.balanceSheet`（backend/src/main/java/com/huicai/base/report/service/impl/ReportServiceImpl.java:34-85）只按科目编码前缀归类：

- `1*`→资产、`2*`→负债、`3*/4*`→权益；
- **`5*` 成本类、`6*` 损益类直接 `continue` 丢弃**；
- **没有"本年利润 / 未分配利润"项**。

会计恒等式 `资产 = 负债 + 所有者权益` 成立的前提是：所有已记账科目要么进资产/负债，要么进权益；损益类（6*）与成本归集类（5*）在期末要么归入存货、要么结转为权益。当前算法把 5/6 两类"漏在表外"，又不把本期净利润补进权益，**只要当期有未结转的收入/费用/成本归集余额，负债表必然不平**。

同文件 `balanceSheetAggregate`（ReportDataMapper.java:113-131）是第二套口径：它把 `5*` 也算进 `total_liab_eq`，与明细法"丢弃 5*"自相矛盾；且该聚合结果在 `balanceSheet()` 里**查了却从未使用**（死查询）。

实证（enterprise_id=1，202401，数据源 t_subject_balance）：

| 科目 | 方向 | end_balance | 现算法归属 |
|------|------|------------|-----------|
| 1002 银行存款 | 借 | 200000.00 | 资产 |
| 1122 应收账款 | 借 | 85800.00 | 资产 |
| 1403 原材料 | 借 | 100000.00 | 资产 |
| 2221.01 销项税额 | 贷 | 9870.80 | 负债 |
| 4001 实收资本 | 贷 | 300000.00 | 权益 |
| 5001 生产成本 | 借（余额为贷 -75929.20） | -75929.20 | **被丢弃** |

现算法：资产 385800.00 vs 负债+权益 309870.80，**差 75929.20**，恰为被丢弃的 5001 余额绝对值。

### 根因 B：销项收入错记 5001（数据 + 部署滞后）

- 销项凭证生成代码早已修复为 6001（commit 7a55a4f，2026-09-11 18:19）；但线上容器 jar 构建于 2026-09-11 01:16，**修复从未部署**。
- 2026-09-13 01:36 环境重置后，旧 jar 的"发票转凭证"把收入贷记到 5001：凭证 JZ2024010003/0004（source=GENERATED）贷记 5001 合计 75929.20。
- 凭证本身**借贷是平的**（12800=11327.43+1472.57；73000=64601.77+8398.23），不是坏分录，而是科目用错 → 撞上根因 A 被丢弃。
- 遗留同源点：`InputInvoiceImportService.java:379` 仍写死 `findSubjectByCode("5001")`（进项侧，此前一直"另议"），需在本期一并定性处理。

### 根因 C：系统对"报表不平"无强拦截

`balanceSheet` 只返回一个 `balanced` 布尔，前端照常展示不平数字；过账、结账链路也不校验资产负债恒等式（结账的 `checkTrialBalance` 只校验"借贷发生额合计相等"，而借贷平 ≠ 资产负债表平）。错误数据可以一路静默流到报表。

## 二、目标（根治标准）

1. **恒等**：任意期间，只要全部已记账凭证借贷平衡，资产负债表必须满足 `资产总计 = 负债合计 + 所有者权益合计`（容差 0.01）。
2. **全科目不遗漏**：1/2/3/4 类直接归类；5 类成本归入"存货"相关资产项；6 类损益净额计入权益项下"本年利润/未分配利润"，与是否已做损益结转兼容且不重复。
3. **单一可信算法**：明细归类与汇总走同一套口径，删除/修复自相矛盾的死聚合查询。
4. **不平可诊断、可拦截**：返回差额与导致不平的科目清单；结账检查纳入资产负债恒等式，不平则阻止结账并给出原因。
5. **防复发**：修正销项/进项科目映射，配套测试；推动修复部署上线。

## 三、输入契约

- 数据源维持 `t_subject_balance`（已含 begin/debit_total/credit_total/end_balance，由过账增量维护）+ `t_subject.direction/code`；不新增表、不改表结构。
- 期间参数 YYYYMM；仅统计本企业、`deleted=0`、`is_active` 科目、leaf 科目（与试算平衡口径一致，父级不重复计）。
- 6 类损益实时净额取自 `t_subject_balance`（POSTED 已反映），与过账增量逻辑同源，不改凭证。

## 四、输出契约（资产负债表项目映射，单一算法）

按科目编码前缀与方向统一归类（signed 规则沿用 58a82fe：1 类借正贷负；2/3/4 类贷正借负）：

| 编码 | 归属 | 说明 |
|------|------|------|
| 1* | 资产（流动/非流动按现有明细行） | 含 1403 原材料 |
| 5001/5101/5201/5301/5401/5403 等成本归集类 | **资产→存货（在产品/工程施工）** | 借余为正在产品；贷余为负（异常映射会在此显性化为负存货） |
| 5402 工程结算 | 资产（存货抵减项，贷余抵减工程施工） | 施工企业专款 |
| 2* | 负债 | |
| 3* | 共同类：借余→资产、贷余→负债 | 按方向落位 |
| 4001/4002/4101/4104/4201 等 | 权益（4201 库存股借余抵减） | |
| **本年利润** | 权益增项 | 见下方"本年利润取数规则" |

### 本年利润 / 未分配利润取数规则（关键）

任一期间 P：
1. 先取 `4103 本年利润` 科目期末余额（结转后有值）。
2. 再取 6 类损益科目当期**未结转净额**：收入类（贷方向，如 6001/6051）贷方发生 - 借方发生，减去成本费用类（6401/6402/6601-6617/6701/6711 等）借方 - 贷方，得到当期净利润 `currentProfit`。
3. `本年利润行 = 4103_end + currentProfit`。
   - 未结转：4103=0，6* 有净额 → 权益补上本期净利润。
   - 已结转（generateProfitCarryOver）：6* 被结平为 0、4103 有值 → 不重复计。
   - 年末利润分配后：4103 转 4104，按 4104 余额体现。
4. 6 类科目**不再**以自身名义出现在负债表（避免与本年利润行重复）。

> 据此，即便把收入误记到 6001（正确）或 5001（错误），报表也能平；但误记 5001 会让"存货"出现异常负数/收入落到在产品，必须由数据与映射层修正（见第八节），不能靠报表掩盖。

### 返回结构（向后兼容扩展，不删既有字段）

在现有 `assets/liabilities/equity/totalAssets/totalLiabilities/totalEquity/totalLiabEquity/balanced` 基础上新增：
- `currentYearProfit`：本年利润行金额；
- `diff`：`totalAssets - totalLiabEquity`（带符号，2 位小数）；
- `unbalancedItems`：导致差额的科目清单 `[{code,name,endBalance,classifiedTo}]`，平衡时为空数组；
- `costInInventory`：5 类归入存货的金额（透明展示）。

## 五、状态流转

不改动业务实体状态机；仅报表读取与结账前置校验（人触发，符合铁律 #1）。

## 六、异常处理

| 场景 | 处理 |
|------|------|
| 数据正常（借贷平、全科目可归类） | 平衡，balanced=true，diff=0，unbalancedItems=[] |
| 存在未结转损益 | 由本年利润行自动补入权益，仍平衡（正常月中状态） |
| 5 类成本有余额 | 归入存货并在 costInInventory 透明展示，仍参与恒等 |
| 底层凭证借贷不平 / 科目错配导致恒等式不等 | balanced=false，返回 diff 与 unbalancedItems；前端显著红字提示"资产负债表不平衡，差额 X，见差异科目"，禁止结账 |
| 科目编码落在 1-6 之外或 direction 缺失 | 列入 unclassified 并计入 unbalancedItems（不再静默 continue 掩盖） |
| 期间无任何数据 | 返回空表、合计 0、balanced=true |

## 九、BDD（Given-When-Then，每场景一个 @Test）

- **场景 1 未结转当期也平衡**：Given 借应收/贷 6001+应交税费 的已记账凭证、未做损益结转 When 查负债表 Then 资产=负债+权益，差额 0，本年利润行=收入净额。
- **场景 2 已结转不重复**：Given 已生成 CLOSE 损益结转凭证（6* 结平、4103 有余额）When 查负债表 Then 本年利润行只取 4103，不与 6* 重复，差额 0。
- **场景 3 成本归集入存货**：Given 5001 生产成本有借方余额 When 查负债表 Then 计入存货（资产），负债表平衡，costInInventory 反映该金额。
- **场景 4 共同类按方向落位**：Given 3* 科目借余/贷余各一 When 查负债表 Then 借余入资产、贷余入负债。
- **场景 5 不平可诊断**：Given 构造恒等式不等的数据（科目无法归类/方向缺失）When 查负债表 Then balanced=false、diff=实际差额、unbalancedItems 含问题科目。
- **场景 6 不平阻止结账**：Given 报表不平衡 When closePeriod Then 抛错且期间状态不变（负向断言：无 UPDATE）。
- **场景 7 两算法口径一致**：删除死聚合后，明细合计与对外 totalXxx 完全一致（对同一组数据断言相等）。
- **回归**：保留 58a82fe 的负债贷余为正、权益贷余为正既有用例。
