## 0. 背景与根因（全部已核验，含现场数据）

### 0.1 现场事实

P94 验收时用户发现：实收资本（4001）年初 300,000.00、期末 200,000.00，"少了 10 万"。核验结论：**报表未做任何减法，是两期数据之间断层**。

| # | 检查项 | 实测结果 |
|---|---|---|
| 1 | 4001 在 202401 / 202407 的 `debit_total` / `credit_total` | 均为 **0.00**（无任何减少动作） |
| 2 | 202401–202407 触及 4001 的凭证（`t_voucher_entry` 关联） | **查无一笔**（减资必须借记资本公积/未分配利润、贷记实收资本） |
| 3 | 202401 期末 vs 202407 期初 | **300,000.00 → 200,000.00**，本应相等 |
| 4 | 两行余额创建时间 / `enterprise_id` | `09-21 17:32` 与 `09-22 07:55`，**同一账套 enterprise_id=1** |
| 5 | 库中有余额数据的期间 | 仅 **202401(3 科目) / 202407(6 科目) / 202409(3 科目)**，202402–202406、202408 空白 |

**定性**：202401 与 202407 是两套各自独立的场景数据，中间 5 个月无余额数据，202407 的 `begin_balance=200000` 系直接写库，绕过了系统自带的滚动逻辑。

### 0.2 根因：既有闸门缺第三项检查

`PeriodCloseServiceImpl#checkBeforeClose` 已做两项并**阻断结账**（L318-320 `throw BusinessException`）：

1. L88-89 `subjectBalanceService.checkTrialBalance(period)` → `balanced`
2. L94 `balanceSheet.get("balanced")` → 资产 = 负债 + 权益

**但对本例两道全部放行**：4001 在 202407 期初 200,000、借 0、贷 0、期末 200,000 → 期间内借贷自洽（试算平衡过）；两期又各自被构造成平的（BS 恒等式过）。**没有任何一项检查"本期期初 == 上期期末"**。

`getPreviousEndBalance`（L520+）虽实现了逐月回溯取上期期末，但**只在 `findOrCreate` 建行时**调用（L506-512）；行已存在（被直接 INSERT/导入造出）则完全绕过，且**建行之后无任何校验**。

### 0.3 危害面

- 断层可长期潜伏：报表、试算平衡、结账闸门全部放行，直到某期对账或审计才暴露
- 错误方向不可控：期初凭空减少会让历史期初与真实投资额不符（本例实收资本少记 10 万，权益被低估）
- 与 P94 的 `yearStartCheckDiff` 互补而非重叠：前者校验**年内恒等式**，本 SPEC 校验**跨期连续性**，两类错误互不覆盖

## 1. 输入契约

- `checkBeforeClose(period)` 入参不变（period，YYYYMM）
- 新增内部比对：本期期初 vs 上期期末，上期口径**必须复用** `getPreviousEndBalance` 的逐月回溯规则（不得另写一套，否则两处口径漂移）
- 仅对**末级科目**（`is_leaf = true`）逐科目比对，沿用 `checkTrialBalance` 的科目过滤口径
- REQ-102：`GET /subject-balance`（或诊断端点）响应新增 `openingContinuity` 字段块
- 权限：沿用结账检查权限，无新增鉴权面

## 2. 输出契约

- **REQ-101**：`checkBeforeClose` 结果新增 `openingContinuity` 子项：
  - `checked`（是否执行了比对；上期无余额数据 → `false`）
  - `skipped` + `skipReason`（新账套首期 / 年中启用 / 上期无数据）
  - `mismatches[]`：`{ subjectCode, subjectName, prevEnd, currentBegin, diff }`，仅含 `|diff| >= 0.01`
  - `mismatchCount`、`maxAbsDiff`
  - `passed` = `mismatches.isEmpty()`；不通过时并入既有 `issues`，**沿用既有阻断机制**（L318-320），不新增阻断代码路径
- **REQ-102**：科目余额表页黄色提示条，列出不平科目 + 上期期末/本期期初/差额，支持点击定位科目；**复用 P97 REQ-100 的规则 id 体系与黄条样式**（如 `OPENING_CONTINUITY`），可与 P97 一并实施
- 错误码：不新增阻断型错误码，沿用 `BusinessException.badRequest` 与既有 `issues` 结构

## 3. 状态流转与副作用

- **纯只读校验**：只 SELECT 余额与科目，不 INSERT/UPDATE/DELETE，不调用 `findOrCreate`（**严禁**在校验过程中建行——否则校验会产生数据副作用，违反铁律 #1）
- 不自动修数、不自动滚动期初、不生成调整凭证（铁律 #1 人是唯一审核主体、#2 只建议）
- 负向断言：校验路径不得改变任何余额行；连续两次调用结果幂等

## 4. 异常处理

| 场景 | 处理 | 级别 |
|---|---|---|
| 上期无余额数据 | `checked=false` + `skipReason`，**不得判为不平**（否则新账套首期永远无法结账） | INFO |
| 本期该科目无余额行 | 跳过该科目（无数据 ≠ 不平），计入 `skippedSubjects` | INFO |
| 非末级科目 | 跳过（余额由末级汇总，避免重复计数） | INFO |
| 差异 ≥ 0.01 | 计入 `mismatches` 并阻断结账 | ERROR |
| 差异 < 0.01 | 视为一致，不列入（容差 0.01，与 P94 同一常量口径） | INFO |
| 科目已逻辑删除 | 跳过 | INFO |

事务：纯只读，无事务需求（不涉及铁律 #11）。

## 验收标准（BDD）

### 场景 1：期初与上期期末不一致时阻断结账（REQ-101）
- **Given** 202407 期初 200,000、202401 期末 300,000（现场同款数据）
- **When** 调用 `checkBeforeClose("202407")`
- **Then** `openingContinuity.passed = false`，`mismatches` 含 4001 且 `diff = -100,000.00`
- **And** 负向断言：`close("202407")` 抛 `BusinessException`，且 `issues` 含期初不连续原因

### 场景 2：期初一致时不得误报（REQ-101）
- **Given** 本期期初 == 上期期末（逐科目）
- **When** 调用 `checkBeforeClose`
- **Then** `openingContinuity.passed = true`，`mismatchCount = 0`
- **And** 负向断言：既有试算平衡与 BS 两项结果不受影响（回归）

### 场景 3：新账套首期/年中启用判为 skip 而非不平（REQ-101）
- **Given** 上期完全无余额数据（如首期 202401）
- **When** 调用 `checkBeforeClose`
- **Then** `checked = false` 且 `skipReason` 非空
- **And** 负向断言：**不得**因无上期数据而阻断结账

### 场景 4：容差与非末级科目处理（REQ-101）
- **Given** 某科目差异 0.005（<0.01）、某父科目有汇总余额
- **When** 校验
- **Then** 0.005 不列入 `mismatches`；父科目不参与比对
- **And** 负向断言：不因父科目重复计入而虚增 `mismatchCount`

### 场景 5：页面黄条提示（REQ-102）
- **Given** 科目余额表期间存在期初不连续科目
- **When** 打开科目余额表
- **Then** 顶部黄色提示条列出科目、上期期末、本期期初、差额
- **And** 负向断言：无不连续时不显示提示条；**不阻断页面渲染、不改任何数据**

### 场景 6：只读铁律（全需求）
- **Given** 执行上述全部校验
- **When** 全流程完成
- **Then** `t_subject_balance` 行数与内容零变化
- **And** 负向断言：校验前后连跑两次 `checkBeforeClose`，`mismatches` 结果完全一致（幂等）

### 场景 7：现场数据回归（真实 DB）
- **Given** 真实库中 202401/202407 断层数据（测试用独立 enterpriseId 构造，不依赖 dev 数据）
- **When** 跑 `OpeningContinuityRealDBTest`
- **Then** 检出 4001 差额 100,000.00
- **And** 负向断言：把 202407 期初改为与 202401 期末一致后不再检出

**测试约束**：每场景一个 `@Test`；Then 至少一正一负断言；跨期比对必须走**真实 DB**（Mock 测不出 `t_subject_balance` 的跨期数据形态——陷阱 4.3-7）。参照 `CashSubjectBalanceRealDBTest` 的增量断言策略避开 seed 污染。

## 竞品对标（铁律 #15）

| 竞品 | 期初连续性控制 | 拦截时机 | 慧财差异 |
|---|---|---|---|
| **用友 NC65** | 「年初重算」明确报错：**期初余额没有数据或数据与上年不一致**；「期初建账」报错"上个会计期间未结账，不允许建账"、"试算不平衡，无法建账"；年结手册要求**按期间从小到大逐期核对**，年初对账无误是全年前提 | 期初建账 / 年结重算（阻断） | 慧财**无任何跨期连续性校验**，断层可永久潜伏 |
| **金蝶云星空** | 结账前系统自检（凭证全审/业务事务处理/**损益结转完成**）不通过则结不了；财务初始余额录入后有「**试算平衡**」按钮一键检查；参数「结账时要求损益类科目余额为零」 | 结账前自检（阻断）+ 录入后自检 | 慧财结账闸门**已有**试算平衡与 BS 平衡两项（不弱于金蝶），但**缺跨期连续性**；无录入后即时自检按钮 |
| **用友 U8** | `gl_accsum` 的 MB/MD/MC/ME 字段；官方排查指引要求按期间从小到大检查，**期初录入错误即对账不平** | 事后对账排查为主 | 慧财缺事前拦截 |
| **SAP FI（F.01）** | carry-forward 校验，期初必须承接上期期末；期间关闭前做完整 balance check | 期间关闭（阻断） | 方向一致，慧财缺实现 |

**结论**：用友与金蝶在"期初/结账"环节均设跨期或整体闸门，**跨期连续性是行业基线而非超前需求**。慧财结账闸门已具备两项检查（不弱于金蝶自检），仅缺跨期连续性一项，**本 SPEC 为补齐基线，非新增能力**。

**变更审计（铁律 #16）**：变更原因=P94 业务验收现场发现断层且两道现有闸门均未拦下；对标结论=上表；影响范围=`PeriodCloseServiceImpl`（结账检查）、`SubjectBalanceService`（新增只读比对方法）、科目余额表前端页（REQ-102）；已同步登记 REQ-2026-101/102 与版本历史 V1.18。
