## 〇、决策记录（老丁 2026-09-14 拍板）

1. **采购借方科目选 A：`1405 库存商品`**（贸易/购入商品入库，销售时结转 6401）。
2. 税额固定 `2221.02 应交增值税-进项税额`（debit），替代误用的 2221.01。
3. 往来保留 `2202 应付账款`（credit）。
4. Flyway V146 为缺该科目的企业（0/1/3/4/5，跳过已有且 deleted 的企业 2 与已删除企业 6）幂等补齐。
5. 科目缺失运行时报 `BusinessException("未配置科目 <code> …")`，禁止旧逻辑的"自动建 P10-2-AUTO 科目"行为。

## 一、背景

P69 修复销项收入误记 5001 时，已在 SPEC 第八节标记：进项侧
`InputInvoiceImportService.createVoucher()`
（backend/src/main/java/com/huicai/sme/tax/service/impl/InputInvoiceImportService.java，约 374-405 行）
存在同类科目误用，且问题比销项更多：

当前采购发票生成的分录是：

```
借：5001 生产成本        row.amount（不含税额）   ← 科目用错（注释甚至写着"销售收入"）
借：2221.01 销项税额     row.taxAmount             ← 进项采购却借了"销项税额"，科目用错
贷：2202 应付账款        row.totalAmount
```

两处错误：
1. 采购成本借方写死 `5001 生产成本`（与销项历史 bug 同源的写死科目）。
2. 进项税借方写死 `2221.01 应交增值税-销项税额`；正确应为 `2221.02 应交增值税-进项税额`。

环境核查（2026-09-14）：
- `source='INVOICE_IMPORT'` 凭证当前 **0 张**，本修复无存量脏数据负担，只改代码与科目种子。
- 科目表中 2221 下**只有 2221.01（销项税额）**；仅 enterprise 2 存在 2221.02（进项税额，debit 方向）。
  enterprise 0/1/3/4/5/6 均**缺 2221.02**，直接 `findSubjectByCode("2221.02")` 会返回 null。
- enterprise 1 已具备 2202 应付账款(id=44)、1405 库存商品(id=16)、6401 主营业务成本(id=81)。

## 二、目标

采购进项发票转凭证使用正确科目，且目标科目缺失时给出明确业务错误（而非 NPE 或静默错记）：

```
借：<采购科目>          row.amount（不含税额）
借：2221.02 进项税额    row.taxAmount
贷：2202 应付账款       row.totalAmount（含税）
```

## 三、输入契约

- 不改接口、不改表结构；入口仍为进项发票确认导入后的"转凭证"。
- 依赖 `t_subject`（按 enterprise_id 隔离）；科目缺失通过 Flyway 种子补齐 + 运行时空值保护。

## 四、输出契约（单一映射）

- 税额：固定 `2221.02 应交增值税-进项税额`（debit 方向），替代当前的 2221.01。
- 往来：保留 `2202 应付账款`（credit）。
- 采购成本借方科目：**待老丁在第六节三选一（会计政策门）**。
- 任一科目按编码查不到时：抛 `BusinessException.badRequest("未配置科目 <code> <name>，请先在科目档案中新增")`，
  不生成半成品凭证（整笔事务回滚）。

## 五、状态流转 / 异常处理

| 场景 | 处理 |
|------|------|
| 三个科目都配置齐全 | 正常生成 DRAFT 凭证，借贷各为 totalAmount，平衡 |
| 缺 2221.02 进项税额 | 明确报错提示先配置科目，不产生凭证 |
| 缺采购科目 / 2202 | 同上，明确报错 |
| 凭证生成后 | 维持 DRAFT，由人工提交→审核→过账（铁律 #1，不自动过账） |

## 六、决策记录：采购借方科目（2026-09-14 已拍板 → 方案 A）

| 选项 | 科目 | 适用 | 影响 |
|------|------|------|------|
| A ✅ 已采纳 | `1405 库存商品` | 采购实物商品入库，后续销售结转 6401 | 资产增加，卖出才进成本，符合本系统已有 1403/1405 存货体系 |
| B（备选） | `6401 主营业务成本` | 采购即耗用、无库存管理 | 直接进当期损益 |
| C（否决） | 按货物智能分流 | 混合经营 | 需在发票行加判定规则，本期不做 |

## 七、Flyway 种子（V146 已实现）

- 文件：`V146__add_input_vat_subject.sql`，为缺少 2221.02 的企业补齐科目，参照 enterprise 2 既有定义：
  `code=2221.02, name=应交增值税-进项税额, direction=debit, parent=2221(动态取各企业 2221 的 id), is_leaf=true, is_active=true`。
- 幂等：`WHERE NOT EXISTS`（按 enterprise_id + code），不覆盖已存在（ent2 保留）。
- 覆盖范围：enterprise 0（系统模板）+ 1/3/4/5（活跃企业缺科目者）；跳过已删除企业 6。仅插入科目，不动任何余额/凭证。
- dry-run 验证：INSERT 0 5，5 家企业正确补入且父科目指向各自 2221（id 272/47/545/636/819）。

## 八、BDD（Given-When-Then，每场景一个 @Test）✅ 已落地

1. 科目齐全：Given 1405/2221.02/2202 都在 When 转凭证 Then 借库存商品(不含税)+借进项税、贷应付(含税)，金额平衡，状态 DRAFT → `createVoucher_正确科目与金额_借贷平衡`
2. 进项税科目正确：生成的税额分录 subject=2221.02，而不是 2221.01 → 同上用例断言 2221.02
3. 缺 2221.02：Given 企业无该科目 When 转凭证 Then 抛 BusinessException 含"未配置科目 2221.02"，且不插入任何凭证/分录（负向断言）→ `createVoucher_缺进项税科目_抛异常且无半成品`
4. 缺采购科目：同上，报错且无半成品凭证 → `createVoucher_缺库存商品科目_抛异常`
5. 金额关系：debit(amount)+debit(tax)=credit(totalAmount) → 用例内断言 1000+130=1130
6. 空值兜底：`requireSubjectByCode` 科目不存在时抛 BusinessException 且不自动建科目 → `requireSubjectByCode_不存在_抛异常不自动建`
