## 概述

核销单状态机为 `DRAFT → SUBMITTED → CONFIRMED → VOUCHERED → REVERSED`。`generate-voucher` 会为核销单生成一张 **DRAFT 制证凭证** 并将 `voucher_id` 挂接到核销单与业务单据上。

**缺陷（幽灵凭证）**：原 `reverse()` 反核销实现只把核销单置为 REVERSED、恢复金额，但**不处理已生成的 DRAFT 制证凭证**，导致：
1. DRAFT 凭证未被作废，成为无人认领的"幽灵凭证"；
2. 核销单 `voucher_id` 仍指向已作废/悬空的凭证；
3. 业务单据 `voucher_id` / `voucher_no` 残留挂接，状态滞留 `VOUCHERED`。

**修复目标**：反核销时联动作废 DRAFT 制证凭证，并清空核销单与业务单据**双侧**凭证挂接；非 DRAFT（已提交/已审核/已过账）凭证按铁律 #3 不可直接作废，必须拦截并提示先红冲凭证。

---

## 1. 输入契约

- `id: Long` — 待反核销的核销单主键（路径参数 `/arap-settlements/{id}/reverse`）

**前置条件**：
- 核销单存在且 `deleted = 0`；
- 核销单状态 ∈ {`CONFIRMED`, `VOUCHERED`}（`ArapStatus.isSettlementReversible`）；
- 若 `voucher_id` 非空，对应凭证状态必须为 `DRAFT`（否则拦截）。

**权限要求**：登录用户（JWT），操作人取自 `SecurityUtils.getCurrentUserId()`，缺省 `DEFAULT_USER_ID`。

---

## 2. 输出契约

- 成功：`R<Void>`，`code=200`；
- 核销单置 `REVERSED`，生成 `-H` 对冲核销单（DRAFT，金额取负）；
- DRAFT 制证凭证被逻辑作废（`t_voucher.deleted=1`），分录物理删除；
- 核销单 `voucher_id` 与业务单据 `voucher_id`/`voucher_no` 清空。

**失败响应**：`BusinessException`，参考全局错误码字典（SPEC-CONTRACT-SCHEMA.md §0.5）。

---

## 3. 状态流转

| 实体 | 合法转换 |
|------|---------|
| 核销单 | `CONFIRMED → REVERSED`、`VOUCHERED → REVERSED` |
| 对冲核销单（新建） | `∅ → DRAFT`（金额取负，编号 `原编号-H`） |
| 制证凭证 | `DRAFT → deleted=1`（逻辑作废） |
| 凭证分录 | `∃ → 物理删除` |
| 业务单据（目标） | 金额回滚后 `settled=0`：凭证已作废 → `VOUCHERED → APPROVED`；凭证未作废 → 保持 `VOUCHERED`；`settled>0` → `PARTIALLY_RECONCILED` |
| 来源单据（RECEIPT/PAYMENT） | `settled=0`：`VOUCHERED→VOUCHERED`（保留）否则 `APPROVED`；`settled>0` → `PARTIALLY_RECONCILED` |
| 来源银行流水（bank_txn） | `MATCHED → UNMATCHED` |

**负向断言**（禁止的跳转）：
- `DRAFT`/`SUBMITTED`/`REJECTED`/`REVERSED`/`CANCELLED` 核销单 **不可** 反核销 → 抛 `BusinessException`；
- 凭证状态非 `DRAFT`（SUBMITTED/AUDITED/POSTED）→ **不可** 直接作废，抛 `BusinessException` 提示先红冲；
- 凭证已作废时业务单据 **不可** 保持 `VOUCHERED`（凭证已不存在）。

**副作用声明（Side Effects）**：
- `DB_UPDATE → t_arap_settlement` → 原核销单置 REVERSED；凭证作废时经 `UpdateWrapper` 显式置空 `voucher_id`（updateById 忽略 null 字段）
- `DB_INSERT → t_arap_settlement` → 对冲核销单（-H，金额取负）
- `DB_INSERT → t_arap_settlement_entry` → 对冲明细（金额取负）
- `DB_UPDATE → t_voucher` → 逻辑作废 DRAFT 凭证（deleted=1）
- `DB_DELETE → t_voucher_entry` → 物理删除凭证分录
- `DB_UPDATE → t_business_doc` → 目标单据金额回滚 + 凭证作废时经 `UpdateWrapper` 显式置空 `voucher_id`/`voucher_no`（实体同时置 null 防 updateById 回写旧值）
- `DB_UPDATE → t_business_doc` → 来源单据（RECEIPT/PAYMENT）金额回滚
- `DB_UPDATE → t_bank_statement` → 来源流水 MATCHED→UNMATCHED
- `DB_UPDATE → t_input_invoice/t_output_invoice` → 发票状态对称回滚（onReconciliationUpdate）
- `DB_INSERT → t_reconciliation_log` → 核销日志（REVERSE）

## 4. 异常处理

| 异常码 | HTTP 状态 | 日志级别 | 提示文案 |
|--------|----------|---------|---------|
| BIZ_SETTLEMENT_NOT_REVERSIBLE | 400 | WARN | 仅已确认或已记账的核销单可反核销， 当前： {status} |
| BIZ_VOUCHER_NOT_DRAFT | 400 | WARN | 核销单已制证且凭证状态为 {status}，请先红冲凭证后再反核销： voucherId={id} |

**降级策略**：发票状态回滚、银行流水标记失败仅 `log.warn`，不阻断反核销主流程。
**事务回滚条件**：`@Transactional(rollbackFor = Exception.class)`，任何未捕获异常整体回滚；乐观锁冲突（`OptimisticLockingFailureException`）经 `@Retryable` 最多重试 3 次。

## 验收标准（BDD）

### 场景 1：已制证（DRAFT 凭证）核销单反核销 — 联动作废并清空双侧挂接
- **Given** 核销单状态 VOUCHERED，`voucher_id=V`；凭证 V 状态 DRAFT；目标业务单据挂 `voucher_id=V`/`voucher_no`，状态 VOUCHERED，已全额核销
- **When** 对核销单执行反核销
- **Then** 凭证 V 逻辑作废（deleted=1）且分录删除；核销单置 REVERSED 且 `voucher_id` 清空；目标单据 `voucher_id`/`voucher_no` 清空、状态回 APPROVED、金额回滚；生成 -H 对冲单（DRAFT，金额取负）
- **And** 核销单不残留 `voucher_id`，目标单据不残留 `voucher_id`/`voucher_no`，不保持 VOUCHERED

### 场景 2：凭证非 DRAFT 时拦截反核销
- **Given** 核销单状态 VOUCHERED，`voucher_id=V`；凭证 V 状态 AUDITED（或 SUBMITTED/POSTED）
- **When** 对核销单执行反核销
- **Then** 抛出 `BusinessException`，提示"请先红冲凭证后再反核销"
- **And** 凭证 V 未被作废，核销单状态不变（未 REVERSED），不生成对冲单

### 场景 3：未制证核销单反核销 — 不涉及凭证
- **Given** 核销单状态 CONFIRMED，`voucher_id` 为空
- **When** 对核销单执行反核销
- **Then** 不作废任何凭证；核销单置 REVERSED；目标单据金额回滚，状态按剩余金额定（VOUCHERED 保持 / APPROVED / PARTIALLY_RECONCILED）
- **And** 不调用凭证删除，目标单据凭证挂接不被清空

### 场景 4：非法状态核销单禁止反核销
- **Given** 核销单状态 DRAFT（或 REVERSED/CANCELLED）
- **When** 对核销单执行反核销
- **Then** 抛出 `BusinessException`，提示"仅已确认或已记账的核销单可反核销"
- **And** 不产生任何写操作

## 修复实现说明（MyBatis-Plus 陷阱）

修复分四轮收敛，核心是 `updateById` **默认忽略 null 字段**（NOT_NULL 策略）这一陷阱被连续踩中三次：

1. **核销单侧**：`entity.setVoucherId(null)` + `updateById` 不生效 → 改 `UpdateWrapper.set("voucher_id", null)`；
2. **单据侧**：`doc.setVoucherId(null)` + `updateById` 同样不生效 → 改 `UpdateWrapper.set("voucher_id", null).set("voucher_no", null)`；
3. **回写覆盖**：仅做 UpdateWrapper 清列但实体仍持旧值 → 后续 `updateById(doc)` 把旧值**回写覆盖** → 最终采用 **实体置 null + UpdateWrapper 显式清列** 双保险。

> 教训（已沉淀 §4.4）：凡需将某列更新为 NULL，必须 `UpdateWrapper.set(col, null)` 显式置空，且实体字段同步置 null 防止 updateById 回写。
