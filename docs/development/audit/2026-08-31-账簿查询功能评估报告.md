## 3. 代码实现评估

### 3.1 文件清单

| 文件 | 职责 |
|------|------|
| `LedgerService`（接口） | 3 个查询：subjectBalance / generalLedger / subsidiaryLedger |
| `LedgerServiceImpl` | 实现，共 142 行 |
| `LedgerController` | 4 个端点：subject-balance / general / subsidiary / trial-balance |
| `SubjectBalanceService` / `Impl` | 余额快照写入（过账时）、期初建账、试算平衡、锁定期初 |
| `VoucherEntryMapper.selectBySubjectIdAndPeriod` | JOIN t_voucher 按期间过滤分录（**2026-08-31 修复跨期间串账**） |
| `SubjectBalanceMapper` | 余额表 CRUD |

### 3.2 逐方法评估

#### `subjectBalance(period)` — 科目余额表
- **逻辑**：读 t_subject_balance 指定期间行 → 逐行 getById 科目 → 过滤非末级 → 组装 Map
- **优点**：期间过滤正确、末级过滤正确
- **问题**：
  1. **N+1 查询**：每条余额行一次 `subjectService.getById()`，451 个末级科目 = 451 次 DB 查询
  2. **返回 `Map<String,Object>` 弱类型**：违反铁律 #13（DTO/VO 隔离），前端拿不到类型保障，序列化字段名靠约定
  3. **无过滤选项**：零余额科目、非零科目、科目范围、科目级别均不可筛（友商标配）
  4. **无本年累计列**（友商标配年初余额/本年累计）
  5. **无分页**：科目数大时一次性全量返回

#### `generalLedger(subjectId, period)` — 总分类账
- **逻辑**：期初行（余额表 begin_balance）→ 逐笔分录滚动余额（按科目方向 debit=+借-贷 / credit=+贷-借）→ 本期合计行
- **优点**：滚动余额计算正确、借贷方向区分正确、有期初/合计行；2026-08-31 修复后期间过滤在 SQL 层完成
- **问题**：
  1. **缺本年累计/上月结转列**（友商总账标配本期借/贷 + 本年借/贷累计）
  2. **返回弱类型 Map**
  3. **无分录日期/凭证号展示**：总账行只有 voucherId，无 voucher_no、无 date
  4. 期初余额取 `begin_balance`，但未校验期间连续性（跨期期初缺失时余额链断裂）

#### `subsidiaryLedger(subjectId, period)` — 明细账
- **逻辑**：仅按科目+期间返回逐笔分录（voucherId/subjectId/code/name/summary/debit/credit/assistJson）
- **问题**：
  1. **缺期初余额行、期末余额行、余额列**（友商明细账标准格式为：日期/凭证号/摘要/借方/贷方/**余额**，且带期初行）
  2. **无日期范围过滤**（PRD §4.5 明确要求）
  3. **无凭证号、无凭证日期**（只有 voucherId）
  4. **assistJson 原样返回字符串**，未解析为结构化辅助核算明细
  5. **无方向列**（借/贷标记靠 debit/credit 是否非零推断）

#### `trialBalance(period)` — 试算平衡（SubjectBalanceService.checkTrialBalance）
- **逻辑**：按借贷方向汇总期初/发生/期末，输出平衡性判断
- **优点**：begin/movement/end 三口径 + 整体 balanced，方向处理正确
- **问题**：基于 t_subject_balance 快照，若期间未过账（快照未生成）则返回全零"平衡"——**存在假阳性风险**（无法区分"真平衡"与"无数据"）

### 3.3 关键缺陷清单

| # | 严重度 | 缺陷 | 证据 |
|---|--------|------|------|
| D1 | 🔴 高 | **辅助核算账 PRD 标完成但未实现**（B-011 / AT-10） | 全库搜索无 auxiliary/multiColumn 账簿查询代码；仅有凭证录入侧校验 |
| D2 | 🟡 中 | **明细账缺日期范围过滤**，PRD §4.5 与 AT-09 要求"科目+期间+日期范围" | subsidiaryLedger 仅 subjectId+period |
| D3 | 🟡 中 | **余额表/总账/明细账均缺本年累计列** | 友商标配；代码无 yearTotal |
| D4 | 🟡 中 | **试算平衡在无快照数据时返回全零"平衡"**（假阳性） | checkTrialBalance 空 balances 时全零 |
| D5 | 🟢 低 | N+1 查询（subjectBalance 每行 getById） | LedgerServiceImpl:37 |
| D6 | 🟢 低 | 返回 Map 弱类型，违反 DTO/VO 铁律 | 全部 3 个方法 |
| D7 | 🟢 低 | 明细账 assistJson 未结构化解析、无余额列 | subsidiaryLedger 实现 |

## 5. 真实数据库数据验证（2026-08-31 快照）

### 5.1 当前数据事实

| 指标 | 值 | 说明 |
|------|-----|------|
| t_voucher | 58 张 | **全部 DRAFT 状态、GENERATED 来源** |
| t_voucher_entry | 154 条 | 对应 58 张凭证 |
| t_subject | 456 个（末级 451） | 科目体系完整 |
| t_subject_balance | **0 行** | 无余额快照 |
| t_account_closure / t_profit_transfer | 0 条 | 无结账记录 |

### 5.2 验证结论

- **余额表 / 总账期初 / 试算平衡在真实库中均返回空** —— 这是**符合逻辑的**：余额快照只在凭证过账（`updateBalanceOnPost`）时写入，当前 58 张凭证全部停留在 DRAFT，从未过账，也未做期初建账。
- **由此暴露一个业务风险**：账簿查询功能当前无法用真实业务数据验证效果。建议走通"期初建账 → 凭证审核 → 过账 → 查询账簿"完整链路后再做业务验收。
- 明细账查询理论上可查到 154 条 DRAFT 分录（selectBySubjectIdAndPeriod 未过滤凭证状态，只过滤 period+deleted）——**这是一个潜在缺陷**：明细账/总账会把未过账（DRAFT/SUBMITTED/AUDITED）凭证的分录也查出来，友商默认"包括未过账凭证"是可选项而非默认。需确认业务预期。

## 7. 改进建议（按优先级）

### P0 — 消除 PRD 与实现漂移
1. **实现辅助核算账查询**（B-011 / AT-10）：按核算维度（CUSTOMER/VENDOR/DEPT/EMPLOYEE/PROJECT）+ 期间汇总余额。需要新增 Mapper 查询（assistJson 是 JSONB，可用 `->>` 提取维度字段分组汇总）
2. **更新 PRD 状态或确认范围**：若辅助核算账本期不做，应将 B-011 状态改回"规划中"，避免文档误导

### P1 — 补齐功能缺口
3. **明细账支持日期范围过滤**（PRD §4.5）：subsidiaryLedger 增加 startDate/endDate，JOIN t_voucher 过滤
4. **余额表/总账/明细账增加本年累计列**
5. **明细账补期初行 + 余额列 + 凭证号/日期**（对齐友商标准格式）

### P2 — 质量与体验
6. **试算平衡区分"真平衡"与"无数据"**：空快照时明确提示"该期间无余额数据"，避免假阳性
7. **过账凭证与账簿查询解耦**：明确"未过账凭证是否入账"策略（默认不含，可选项含）
8. **消除 N+1**：subjectBalance 用 `selectByIds` 批量查询科目
9. **返回类型 VO 化**：定义 SubjectBalanceVO/LedgerRowVO，替代 Map

### 测试建议
10. **补充 T2~T5 边界测试**（期初为 null、试算平衡空数据、未过账凭证是否入账策略）
11. **增加账簿查询真实 DB 链路测试**：过账凭证 → 校验余额快照 → 查询总账/明细账/余额表贯通
