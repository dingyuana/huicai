# 慧财底座+双分支架构开发计划

> **分支**：`feature/architecture-base-branch`
> **版本**：V1.0 | **日期**：2026-07-19
> **设计思想**：SDD+BDD+TDD 三驱动、三步闭环（SPEC→Plan→审核→执行）、Human-in-the-loop、确定性/非确定性分离

---

## 一、设计思想（贯穿全计划）

### 1.1 核心铁律

| 铁律 | 含义 | 违反后果 |
|------|------|---------|
| 三步闭环 | 任何开发=SPEC→Plan→审核→执行，**跳步直接违规** | 回滚重做 |
| SDD四段模板 | 每个SPEC必须包含：输入契约、输出契约、状态流转、异常处理 | PR不通过 |
| BDD Given-When-Then | 验收标准必须用BDD格式，每个场景对应一个@Test | 测试门禁拦截 |
| YAML契约块 | 每个SPEC尾部必须附machine-readable YAML contract | CI校验失败 |
| Human-in-the-loop | 所有审核人工完成，AI只出建议 | 财务违规 |
| 确定性/非确定性分离 | 凭证/结账/折旧=Java，科目推荐/异常检测=Python | 架构走偏 |
| 先查现有方案 | 新建任何模块前先检查开源/现有方案是否满足 | 重复造轮子 |
| 修bug全量扫描 | 修一个bug后全量同类扫描，不只修当前点 | 隐藏bug |
| 测试门禁 | 交付前 `mvn test` 0新增失败，compile≠完成 | 不可提交 |
| 文档同步 | 代码变更后必须同步设计文档 | 治理审计不通过 |

### 1.2 技术栈约束

**保留**：Spring Boot 3.x + MyBatis-Plus + PostgreSQL 16 + Vue 3 + Element Plus + Redis + RabbitMQ + MinIO + FastAPI + LangChain + pgvector

**不引入**：微服务/K8s/Nacos/ClickHouse/Milvus/Drools/Seata/Kafka。单体部署，不改变现有技术栈。

### 1.3 开发流程

```
┌─────────────────────────────────────────────────────────────┐
│                        三步闭环                              │
│                                                             │
│  SPEC → 老丁审核 → Plan → 老丁审核 → 开发(微循环) → 测试 → 提交  │
│   ↑                                                 │        │
│   └────────────── 审核不通过回退 ──────────────────┘        │
│                                                             │
│  微循环（开发阶段）：Contract-First → TDD Red → Green → Refactor │
│  每次提交前：mvn test 0新增失败                                │
└─────────────────────────────────────────────────────────────┘
```
