> **编号**：HUICAI-DEV-001
> **版本**：V2.0 | **修改日期**：2026-07-07 | **修改人**：Hermes
> **修改内容**：V2.0 更新——P0/P1/P2全部完成，P3远期规划，技术栈修正（去掉K8s），关联P0-P3-roadmap

## 一、项目概况

| 项目 | 内容 |
|------|------|
| 名称 | 慧财财务（Web 版财务软件） |
| 技术栈 | Spring Boot 3.x + PostgreSQL 16 + Vue 3 + Element Plus |
| 数据库 | PostgreSQL 16（pgvector + pg_trgm），Redis 7，MinIO |
| 基础货币 | 人民币（RMB），`NUMERIC(18,2)` |
| 部署 | Docker Compose（开发+生产），不引入K8s |
| 定位 | 单体起步，微服务可选演进 |

## 二、总体原则

### 开发顺序优先级

```
基础 → 业务 → 财务核心 → 扩展

Phase 0: 项目骨架 & 基础设施
  ↓
Phase 1: 系统管理 + 基础数据 ← 一切的前提
  ↓
Phase 2: 用户权限 (RBAC) ← 安全屏障
  ↓
Phase 3: 财务核心（科目→凭证→账簿→结账）← 核心命脉
  ↓
Phase 4: 业务单据管理 ← 凭证的数据入口
  ↓
Phase 5: 出纳管理 ← 资金管理
  ↓
Phase 6: 固定资产 ← 资产管理
  ↓
Phase 7: 往来管理（应收/应付/核销）← 客户/供应商
  ↓
Phase 8: 税务管理 ← 合规
  ↓
Phase 9: 预算管理 ← 控制
  ↓
Phase 10: 报表中心 + 财务分析 ← 输出
  ↓
Phase 11: AI 服务层（Python 微服务）← 增强
```

### 关键设计约束（从说明书提炼）

1. **凭证不可篡改** — 已审核/已记账只能红冲，不能修改
2. **AI 在环** — 所有 AI 结果必须人工确认后才能生效
3. **严格状态机** — 所有核心实体有明确状态流转
4. **序列号** — Redis INCR 生成，格式 `类型+期间+流水号`
5. **数据权限** — MyBatis 拦截器注入 SQL 条件
6. **审计日志** — AOP + jsonb 快照
7. **事务原子性** — 涉及凭证的操作全部 `@Transactional`
8. **并发控制** — 科目余额用乐观锁或行锁
9. **结账顺序** — 折旧→工资→税金→成本结转→损益结转→结账

## 六、Phase 3：财务核心（科目→凭证→账簿→结账）（估算：10-15 天）

### 6.1 模块拆解

| # | 子任务 | 说明 |
|---|--------|------|
| 3.1 | 期初建账 | 末级科目录入期初余额，上级自动汇总，试算平衡 |
| 3.2 | 科目余额管理 | 实时更新 + 期间快照 `t_subject_balance` |
| 3.3 | 凭证录入 | 手工录入，借贷平衡校验，科目有效性校验 |
| 3.4 | 凭证审核/记账 | 状态流转：草稿→提交→审核→记账 |
| 3.5 | 凭证红冲 | 生成红字凭证，记录 `reversed_from` |
| 3.6 | 凭证模板 | `t_voucher_template` 科目映射模板 |
| 3.7 | 总分类账/明细账 | 按科目/期间/辅助核算维度查询 |
| 3.8 | 日记账/多栏账 | 按科目+日期范围查询 |
| 3.9 | 期末结转向导 | 严格顺序执行，结账检查清单 |
| 3.10 | 自动结转模板 | 损益结转、成本结转一键生成 |
| 3.11 | 反结账 | 最高权限，记录日志 |
| 3.12 | 年结 | 余额转下年，年结凭证 |

### 6.2 数据库表
- `t_voucher` — 凭证主表（含 `detail_json`、`ai_tags`）
- `t_voucher_entry` — 凭证分录（含 `embedding` vector 列）
- `t_subject_balance` — 科目余额（复合主键 `subject_id + period`）
- `t_voucher_template` — 凭证模板
- `t_period_close_log` — 结账日志

### 6.3 核心业务规则
- **借贷必平衡**：`SUM(debit) = SUM(credit)` 硬约束
- **凭证号生成**：Redis INCR，格式 `类型+YYYYMM+序列`
- **已记账不可改**：只能红冲，`reversed_from` 关联
- **余额实时更新**：凭证记账时更新 `t_subject_balance`
- **结账顺序不可逆**：折旧→工资→税金→成本→损益→结账

## 十七、MVP 建议（最小可行产品）

如要优先交付可用的最小版本，建议：

**MVP 范围**（Phase 0 + 1 + 2 + 3 + 部分 4 + 部分 10）：
1. 科目管理 + 期初建账
2. 凭证录入/审核/记账
3. 总账+明细账查询
4. 科目余额表
5. 期末结账（基本）
6. 资产负债表 + 利润表

**MVP 排除**：
- 固定资产、预算、AI 服务、自定义报表、财务分析、税务全模块
- 单据管理（仅保留基础→凭证的入口）
- 出纳管理（仅保留基础日记账）

**MVP 目标**：用户可以建账→做凭证→出报表→结账，完成基础财务闭环。
