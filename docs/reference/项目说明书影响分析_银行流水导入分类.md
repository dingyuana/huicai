**位置**：在"支持的单据类型"列表后，插入以下内容：

---

**银行流水导入流程**：

银行流水是系统的核心数据入口之一。导入流程如下：

```
上传对账单（Excel/CSV）
  ↓
列名智能识别
  ├─ 日期列: "交易日期"/"记账日期"/"date"
  ├─ 摘要列: "摘要"/"备注"/"description"
  ├─ 金额列: "收入金额"/"支出金额"/"金额"
  └─ 对方户名: "付款人名称"/"收款人名称"/"对方户名"（四层级联）
  ↓
自动分类引擎（两段式）
  ├─ 规则引擎（确定性匹配）
  │    优先级排序 → 方向过滤 → 关键词/正则匹配 → 第一命中即停
  │    8 类标准分类: bank_fee/interest_income/business_receipt/
  │                  business_payment/internal_transfer/tax_payment/
  │                  social_security/insurance_fee
  └─ 兜底启发式分类（关键词分组，确保100%有结果）
  ↓
待确认 → 人工审查 → 确认/重分类 → 生成单据/凭证
```

导入后流水状态流转：`已分类（待确认）→ 已确认 → 已生成单据 → 已生成凭证 → 已核销`

**§4.5.1 智能分类引擎（规则引擎 + 兜底启发式）**

系统采用**两段式分类策略**，确保每条流水均有分类结果：

**第一段：分类规则引擎**

规则存入 `t_classification_rule` 表，系统管理员可通过前端管理。规则属性：

| 属性 | 说明 |
|------|------|
| name | 规则名称，如"银行手续费" |
| rule_type | 匹配类型：keyword（包含）、keyword_regex（\| 分隔多关键词）、counterparty_match（对手方匹配）|
| pattern | 匹配模式，如"手续费\|工本费\|年费" |
| match_field | 匹配字段：description（摘要）或 counterparty（对方户名）|
| direction | 方向过滤：in（收入）、out（支出）、空（不限）|
| classification | 分类结果：bank_fee / interest_income / business_receipt / ... |
| priority | 优先级（数字越小越优先）|

匹配逻辑：所有活跃规则按优先级排序，逐条检查方向→关键词，**第一命中即停**。

**第二段：兜底启发式分类**

无规则命中时，使用硬编码关键词分组按优先级匹配：

| 优先级 | 分组 | 分类 | 示例关键词 |
|--------|------|------|-----------|
| 1 | 银行费用 | bank_fee | 手续费、工本费、年费、短信费 |
| 2 | 利息收入 | interest_income | 利息、结息、派息 |
| 3 | 保险费用 | insurance_fee | 保险、保费、投保 |
| 4 | 税务缴费 | tax_payment | 税、增值税、所得税、城建税 |
| 5 | 社保缴费 | social_security | 社保、公积金、养老、医疗 |
| 6 | 工资发放 | salary_payment | 工资、薪金、奖金、补贴 |
| 7 | 内部转账 | internal_transfer | 转账、转存、调拨 |
| 8 | 业务收款(in) | business_receipt | 货款、回款、结算款 |
| 9 | 业务付款(out) | business_payment | 货款、付款、采购款 |
| 10 | 兜底 | pending | 归入待处理流水池 |

### 更新 3：§4.12 AI 辅助模块 — 补充规则引擎定位

**位置**：在 §4.12 开头（"AI 模块为独立 Python 微服务..." 之后），追加：

---

> **规则引擎与 AI 服务的分层定位**：
>
> 系统采用"规则引擎 + AI 语义 + 兜底启发式"三层分类架构：
>
> ```
> 优先级:  规则引擎(高) > AI 语义(中) > 兜底启发式(低)
>              ↓              ↓              ↓
>           确定性高         灵活性强      100%有结果
>           Java 本地       Python 微服务   Java 本地
> ```
>
> - **规则引擎**（Java 本地实现）：银行手续费、利息、税费等高频确定性场景，不依赖 AI 服务可用性
> - **AI 语义**（Python 微服务）：陌生对手方、模糊摘要、费用类型推荐，需人工审核确认
> - **兜底启发式**（Java 本地）：确保每笔流水有分类，永不丢单
>
> 三个层次互相补充，无 AI 服务时系统仍能正常运行（规则+兜底），AI 仅在需要时提升准确率。

**位置**：在 §4.12.2 自动对账与智能匹配末尾，补充：

---

**银行流水智能分类（新增）**：

1. 规则引擎无法分类的流水（置信度<60%），触发 AI 语义分类
2. Java 后端创建 AI 任务（`AiTaskService.createAndDispatch`），通过 RabbitMQ 投递至 Python 匹配服务
3. Python 服务对摘要文本进行嵌入（`text2vec-base-chinese`），与历史分类模板计算语义相似度
4. 返回建议分类 + 置信度评分
5. AI 结果写入 `t_bank_statement.ai_suggested_action` + `ai_confidence` + `ai_business_scene`
6. 前端展示置信度标签（≥80 绿色 / 60-79 黄色 / <60 灰色），出纳一键确认或手动修正
7. 人工修正记录写入 `t_ai_feedback_log`，用于后续模型微调

### 更新 4：§5.2 建表语句 — 新增两张表

**位置**：在 `-- AI 任务表` 之后追加：

```sql
-- 分类规则表
CREATE TABLE t_classification_rule (
    id                 BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    tenant_id          BIGINT NOT NULL,
    name               VARCHAR(100) NOT NULL,
    rule_type          VARCHAR(30) NOT NULL DEFAULT 'keyword',
    pattern            TEXT NOT NULL,
    match_field        VARCHAR(30) NOT NULL DEFAULT 'description',
    direction          VARCHAR(10),
    classification     VARCHAR(50) NOT NULL,
    priority           INT NOT NULL DEFAULT 0,
    is_active          BOOLEAN NOT NULL DEFAULT TRUE,
    debit_subject_id   BIGINT,
    credit_subject_id  BIGINT,
    created_by         BIGINT,
    updated_by         BIGINT,
    created_at         TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at         TIMESTAMP NOT NULL DEFAULT NOW(),
    deleted            INT DEFAULT 0
);
CREATE INDEX idx_cls_rule_tenant ON t_classification_rule(tenant_id, is_active, priority);

-- AI 反馈日志表（记录人工修正，用于模型学习）
CREATE TABLE t_ai_feedback_log (
    id                   BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    tenant_id            BIGINT NOT NULL,
    bank_txn_id          BIGINT NOT NULL,
    ai_suggested_action  VARCHAR(50),
    ai_confidence        INT,
    ai_business_scene    VARCHAR(100),
    human_action         VARCHAR(50) NOT NULL,
    human_modified_fields JSONB,
    created_by           BIGINT,
    created_at           TIMESTAMP NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_ai_feedback_txn ON t_ai_feedback_log(bank_txn_id);
CREATE INDEX idx_ai_feedback_tenant ON t_ai_feedback_log(tenant_id);
```
