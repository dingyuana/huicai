## 一、核心设计理念

| 理念 | 说明 |
|:---|:---|
| **效率优先** | 批量导入应 5 秒内完成解析，自动分类率达到 80% 以上 |
| **100% 有结果** | 每条导入流水必须有分类结果，绝不因规则不足而丢单 |
| **AI 辅助，人审为终** | 规则引擎和 AI 仅提供建议，最终分类需人工确认生效 |
| **可配置性** | 分类规则由系统管理员配置，无需改代码 |
| **全操作可追溯** | 每次分类、确认、修改均记录操作日志 |

| 角色 | 职责 |
|:---|:---|
| **出纳** | 导入银行对账单；核对自动分类结果；处理待处理流水池；确认/驳回/重分类 |

## 三、业务流程

### 3.1 主流程

```
┌─────────────────────────────────────────────────────────────┐
│                    第一步：文件导入                           │
│  上传 Excel/CSV → 列名智能识别 → 数据预校验 → 预览确认       │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                    第二步：自动分类                           │
│  规则引擎匹配 → 兜底启发式 → (可选) AI 语义增强               │
│  8 类标准分类 + pending(待处理)                              │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                    第三步：人工审查                           │
│  出纳工作台 → 查看分类结果 → 确认/驳回/重分类                 │
│  高置信度(≥80)一键确认，低置信度(<60)建议人工判断             │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                    第四步：后续处理                           │
│  确认后 → 根据分类触发对应流程                               │
│  bank_fee/interest_income → 直接生成凭证                     │
│  business_receipt/payment → 生成业务单据 → 核销发票          │
│  pending → 归入待处理流水池 → 人工指定类型                    │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 待处理流水人工处理流程

当流水无法自动分类（规则引擎 + 兜底均未命中，或出纳主动标记为待处理），进入人工处理工作台：

**场景 A：人工生成收款单**
- 根据流水对方户名查找关联客户档案
- 系统列出该客户所有未核销销售发票
- 出纳手工匹配核销，生成收款单 + 凭证

**场景 B：人工生成付款单**
- 根据流水对方户名查找关联供应商档案
- 系统列出该供应商所有未核销采购发票
- 出纳手工匹配冲销，生成付款单 + 凭证

**场景 C：银行费用/利息/转账**
- 直接确认为银行费用单/利息收入单/银行转账单
- 自动生成凭证，无需核销

## 四、功能需求

### FR-1: 文件导入

#### FR-1.1 文件格式支持

| 属性 | 要求 |
|:---|:---|
| 格式 | .xlsx / .xls / .csv |
| 编码 | 自动检测 UTF-8、GBK、GB18030 |
| 大小 | 单个文件 ≤ 20MB |
| 行数 | 单次导入 ≤ 5000 行 |

#### FR-1.2 列名智能识别

两阶段匹配机制：

- **Phase 1（精确匹配）**：列名与候选名完全一致（不区分大小写）
- **Phase 2（子串匹配）**：列名包含候选名字符串（支持"交易日期[Transaction Date]"这类混合列名）
- **级联回退**：当主列缺失时自动尝试次列、三级列

**日期列**（至少识别一种）：
`交易日期` / `记账日期` / `发生日期` / `日期` / `date` / `transaction date` / `txn date`

**摘要列**（含级联回退）：
`摘要` → `交易附言` / `备注` / `remarks` → `用途` / `purpose`

**金额列**（三列互斥逻辑）：
- 优先：`收入金额`/`贷方金额`/`income`/`credit` + `支出金额`/`借方金额`/`expense`/`debit`
- 降级：`金额`/`发生金额`/`交易金额`/`amount`（正值=收入，负值=支出）

**对方户名列**（四层级联）：
1. `付款人名称`（direction=in）/ `收款人名称`（direction=out）
2. 另一方名称
3. `对方户名` / `对方名称` / `对方账户` / `交易对方` / `counterparty`
4. `付款人` / `收款人`

**参考号/流水号列**（可选）：
`流水号` / `交易流水号` / `交易编号` / `reference` / `voucher no`

#### FR-1.3 预览与确认

- 解析结果以表格形式展示（日期/摘要/金额/对方户名/方向/系统建议分类）
- 列名识别结果默认显示在表头
- 校验失败行红色高亮，鼠标悬浮显示错误原因
- 用户可勾选/取消勾选待导入行
- 确认导入后显示导入结果摘要：共解析 N 条，成功 N 条，跳过 N 条（重复），失败 N 条
- 支持下载错误报告 CSV

### FR-2: 智能分类引擎

#### FR-2.1 分类规则引擎

**规则属性**：

| 属性 | 类型 | 说明 |
|:---|:---|:---|
| name | String | 规则名称，如"银行手续费" |
| rule_type | Enum | keyword（包含匹配）/ keyword_regex（\| 分割多关键词）/ counterparty_match（对手方匹配）|
| pattern | String | 匹配模式，规则引擎专用语法 |
| match_field | Enum | description（摘要）/ counterparty（对方户名）|
| direction | Enum | in（收入）/ out（支出）/ 空（不限）|
| classification | Enum | 分类结果（8 种标准分类 + pending）|
| priority | Int | 优先级，数字越小越优先 |
| is_active | Boolean | 启用/禁用 |
| debit_subject_id | Long | 借方科目（可选，用于自动凭证）|
| credit_subject_id | Long | 贷方科目（可选，用于自动凭证）|

**匹配规则**：

1. 规则按 `priority ASC` 排序
2. 若规则指定 `direction` 且与当前流水方向不符 → 跳过
3. 根据 `match_field` 确定匹配文本（摘要或对方户名）
4. 根据 `rule_type` 执行匹配：
   - `keyword`：匹配文本包含 pattern（不区分大小写）
   - `keyword_regex`：pattern 按 `|` 分割为多个子关键词，任一子关键词包含即匹配
   - `counterparty_match`：同 keyword，但在对方户名字段上执行
5. **第一命中即停**，不再检查后续规则

**8 类标准分类**：

| 分类值 | 中文名 | 说明 |
|:---|:---|:---|
| bank_fee | 银行费用 | 手续费、工本费、年费、账户管理费 |
| interest_income | 利息收入 | 存款利息、结息 |
| business_receipt | 业务收款 | 客户回款、货款收入 |
| business_payment | 业务付款 | 供应商付款、货款支出 |
| internal_transfer | 内部转账 | 账户间调拨、转存 |
| tax_payment | 税务缴费 | 增值税、所得税、城建税等 |
| social_security | 社保缴费 | 社保、公积金 |
| insurance_fee | 保险费用 | 财产险、责任险等 |
| pending | 待处理 | 无法自动分类，归入人工处理池 |

#### FR-2.2 兜底启发式分类

当规则引擎未命中时，触发硬编码关键词组匹配。关键词组按优先级判定：

| 优先级 | 分组 | 分类 | 触发示例 |
|:---|:---|:---|:---|
| 1 | 银行费用 | bank_fee | 手续费/工本费/年费/短信费/汇费/网银费 |
| 2 | 利息收入 | interest_income | 利息/结息/派息/存款利息 |
| 3 | 保险费用 | insurance_fee | 保险/保费/投保/财产险 |
| 4 | 税务缴费 | tax_payment | 税/增值税/所得税/城建税/教育费附加 |
| 5 | 社保缴费 | social_security | 社保/公积金/养老/医疗/失业/工伤/生育 |
| 6 | 工资发放 | salary_payment | 工资/薪金/奖金/补贴/津贴 |
| 7 | 内部转账 | internal_transfer | 转账/转存/调拨/上划/下拨 |
| 8 | 业务收款(in) | business_receipt | 货款/回款/结算款/预收款 |
| 9 | 业务付款(out) | business_payment | 货款/付款/采购款/预付款 |
| 10 | 兜底 | pending | 以上均未命中 |

#### FR-2.3 AI 语义增强（可选）

当规则引擎和兜底均无法给出高置信度结果时，可选调用 AI 微服务进行语义理解：

- 触发条件：`ai_confidence < 60`（需启用 AI 服务）
- 输入：`description + counterparty_name + amount + direction`
- 输出：`suggested_classification + confidence + business_scene`
- 结果仅写入 `ai_*` 字段，不作为最终分类，需人工确认

### FR-3: 人工审核工作台

#### FR-3.1 统计面板

出纳工作台顶部展示 4 个统计卡片：
- 本月流水总数
- 待确认数量
- AI 已处理数量
- 待处理（pending）数量

#### FR-3.2 流水列表

| 列 | 说明 |
|:---|:---|
| 日期 | 交易日期 |
| 摘要 | 交易摘要 |
| 对方户名 | 对方户名（已关联客商显示链接图标）|
| 收入/支出 | 金额（红蓝方向色）|
| **分类** | 彩色标签 + 置信度（如有 AI 建议）|
| 匹配状态 | unmatched / matched / confirmed |
| 操作 | 确认 / 重分类 / 生成单据 / 查看详情 |

**筛选条件**：分类、匹配状态、日期范围、摘要关键词

#### FR-3.3 确认操作

- 确认后流水状态变更为 `confirmed`
- 根据分类自动触发后续处理：
  - `bank_fee` / `interest_income` → 直接生成凭证
  - `business_receipt` / `business_payment` → 生成业务单据（待核销）
  - `internal_transfer` → 生成银行转账单
  - `tax_payment` / `social_security` / `insurance_fee` → 生成凭证
  - `pending` → 弹出人工处理对话框

### FR-4: 规则管理前端

**规则列表页**：

- 表格展示：优先级、规则名称、匹配模式、方向、分类、状态（启用/禁用）、操作
- 拖拽排序（同租户内）
- 搜索/筛选
- 批量启用/禁用

**规则编辑弹窗**：

- 名称（必填）
- 匹配模式（必填）
- 匹配字段：摘要 / 对方户名
- 方向：不限 / 收入 / 支出
- 分类（下拉选择 8 类标准分类）
- 优先级（自动计算，可手动调整）
- 启用状态
- 借方科目/贷方科目（可选，用于生成凭证）

## 六、API 设计

| 方法 | 路径 | 说明 | 关键请求/响应 |
|:---|:---|:---|:---|
| POST | `/api/v1/bank-statements/preview` | 预览 Excel 内容 | Req: multipart file。Res: `{columns, sample, totalRows}` |
| POST | `/api/v1/bank-statements/import` | 导入银行流水 | Req: multipart file + `bankAccountId`。Res: `{total, success, failed, duplicate, failedRows}` |
| GET | `/api/v1/bank-statements/page` | 分页查询 | Query: `accountId, status, classification, startDate, endDate, keyword, page, size` |

| POST | `/api/v1/bank-statements/batch-confirm` | 批量确认 | Req: `{ids: [...]}`。Res: `{confirmed, failed, vouchersCreated, documentsNeeded}` |
| GET | `/api/v1/classification-rules` | 规则列表 | Res: `{data: [rule, ...]}` |
| POST | `/api/v1/classification-rules` | 创建规则 | Req: `{name, ruleType, pattern, matchField, direction, classification, priority}` |
| PUT | `/api/v1/classification-rules/{id}` | 更新规则 | Req: 同上（可选字段）|
| DELETE | `/api/v1/classification-rules/{id}` | 删除规则 | |
| POST | `/api/v1/classification-rules/reorder` | 排序 | Req: `{ruleIds: [有序ID列表]}` |
| POST | `/api/v1/classification-rules/seed` | 初始化种子规则 | Res: `{message: "seeded"}` |
| POST | `/api/v1/classification-rules/match` | 单笔测试匹配 | Req: `{description, counterparty, direction}`。Res: `{matched, ruleId, ruleName, classification}` |
