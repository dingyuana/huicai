## 1. 产品定位

慧财财务系统是一款面向**中小微企业**和**财务代理公司**的纯财务流程管理系统。

采用"**一套底座引擎，双端场景赋能**"的架构：
- **底座（Base）**：科目体系、凭证引擎、会计期间、报表引擎、权限体系等所有企业通用的财务骨架
- **SME 分支**：面向中小微企业的一站式财务闭环（发票、核销、银行流水、资产、报销、工资、预算）
- **Agency 分支**：面向代账公司的多客户批量处理引擎（多账套、批量操作、CRM）

## 2. 目标用户

| 用户类型 | 使用场景 | 核心诉求 |
|---------|---------|---------|
| 中小微企业主 | 自己管账 | 极简操作、自动合规、随时看经营状况 |
| 中小企业财务人员 | 日常记账 | 发票→凭证→报表全流程自动化 |
| 代账公司会计 | 批量处理多家客户 | 批量导入/审核/结账/报税，提效降本 |
| 代账公司老板 | 管理客户 | 服务交付监控、续费管理、团队效率 |

## 3. 设计理念

### 3.1 三大铁律

| 铁律 | 说明 | 违反后果 |
|------|------|---------|
| **人是唯一审核主体** | 所有审核/状态变更必须由人主动触发，系统/AI不允许自动审核 | 财务违规，不可接受 |
| **AI 输出 = 建议** | AI 永远不自动应用到财务数据，结果必须人工确认后落库 | 架构走偏 |
| **凭证不可变性** | 已审核/已过账凭证只能红冲修正，不可直接修改 | 数据一致性破坏 |

### 3.2 开发范式

**SDD（Spec-Driven Development）+ BDD（Behavior-Driven Development）+ TDD（Test-Driven Development）三驱动：**

| 环节 | 谁做 | 产出 |
|------|------|------|
| SPEC 编写 | 人（AI辅助） | 四段模板（输入/输出/状态流转/异常处理）+ BDD Given-When-Then |
| 契约定义 | 人+AI | YAML 机器可读契约块 |
| 测试编写 | 人（不可被AI篡改） | 每个 BDD 场景对应一个 @Test |
| 代码实现 | AI | 严格按 SPEC+测试 生成 |
| 代码审查 | 人 | 核心逻辑、并发、金额精度 |

**三步闭环开发流程：**
```
SPEC → 老丁审核 → Plan → 老丁审核 → 开发(微循环) → 测试 → 提交
                                          ↓
                                    Contract-First → TDD Red → Green → Refactor
```

### 3.3 技术哲学

| 原则 | 含义 |
|------|------|
| 确定性/非确定性分离 | 凭证/结账/折旧=Java（确定性），科目推荐/异常检测=Python（非确定性） |
| 单体部署 | 不引入微服务/K8s/Nacos，降低运维复杂度 |
| 核心算法不依赖AI | 折旧计算、核销算法、个税计算都是纯数学公式，AI不介入 |
| 先查现有方案 | 新建任何模块前先检查开源/现有方案是否满足，避免重复造轮子 |

### 4.2 明确不做（当前版本）

- 销售/采购业务流程（只做财务侧）
- 移动端原生App（必要时做H5响应式）
- 银企直连（保持Excel导入，除非客户明确需要）
- 合并报表（集团客户场景，非当前需求）
- 电子会计档案（财政部新规，非MVP必需）
