# PRD 需求合理性评估（务实版）

> **评估原则**：中小企业财务系统 ≠ 大型 ERP。不追求功能全，追求做精核心场景。
> **评估标准**：P0=必须做 / P1=可以晚点做 / ❌=过度设计，不做

## 三、模块三：业务管理模块（biz）

### 核心判断：采购/销售/库存模块 → ❌ 不做 / 大幅简化

**理由**：中小企业通常使用**独立的进销存 ERP 系统**（如用友畅捷通、金蝶精斗云等）管理进销存，不会用财务系统的"附赠"进销存模块。强行做采购/销售/库存管理，既做不好又和现有系统重叠。

**替代方案**：通过 **导入/导出接口** 与外部进销存系统对接，财务系统只管理应收应付（资金流），不管理实物流。

| 功能 | 评估 | 理由 |
|------|------|------|
| 采购订单 | ❌ 不做 | 进销存系统的事 |
| 采购入库单 | ❌ 不做 | 同上，通过 BusinessDoc 接收外部数据即可 |
| 采购退货单 | ❌ 不做 | 同上 |
| 销售订单 | ❌ 不做 | 进销存系统的事 |
| 销售出库单 | ❌ 不做 | 同上 |
| 销售退货单 | ❌ 不做 | 同上 |
| 其他入库/出库 | ❌ 不做 | 同上 |
| 库存盘点单 | ❌ 不做 | 同上 |
| 库存调拨单 | ❌ 不做 | 同上 |
| 库存台账导出 | ❌ 不做 | 同上 |
| 应收单管理 | ✅ P0 | 已有，**这是财务系统核心** |
| 收款单录入 | ✅ P0 | 已有 |
| 预收单录入 | ✅ P0 | 已有 |
| 应收核销匹配 | ✅ P0 | 已有 |
| 账龄分析表 | ✅ P0 | 已有 |
| 账龄分析表导出 | ✅ P0 | **催款/坏账计提必需** |
| 应付单管理 | ✅ P0 | 已有 |
| 付款单录入 | ✅ P0 | 已有 |
| 预付单录入 | ✅ P0 | 已有 |

## 九、最终建议：做减法

```
PRD 要求：150 项
✅ P0 必须做：35 项（23%）— 大部分已有
✅ P1 可以晚：20 项（13%）
✅ P2 值得做：25 项（17%）
❌ 过度设计：70 项（47%）
```

**近一半的 PRD 功能不适合中小企业财务系统**，建议果断砍掉。聚焦做精 35 项 P0 核心功能，把 20 项 P1 功能作为近中期目标，其余延后或放弃。

**建议下一步**：补齐 P0 第一梯队的 6 项（约 4 天工作量），然后进入下个开发阶段。
