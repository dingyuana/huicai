# 慧财财务 — 需求分析书 04：智能审核与报销

> 对应项目说明书：§4.4 财务核心、§4.12.4 异常检测

---

## 1. 业务概述

凭证审核是财务内控的关键环节。传统模式下，会计/财务经理需逐张审核凭证的科目合理性、金额准确性、附件完整性，耗时且容易疏漏。同时员工报销流程繁琐，财务初审工作量大。

本模块通过 AI 实现凭证的自动化合规检查、异常检测，以及员工报销的智能辅助审核，将简单审核工作前置到系统层。

## 2. 功能需求

### FR-AUDIT-01: 智能凭证审核

**1.1 合规性检查**

| 检查项 | 说明 | 严重度 |
|:---|:---|:---:|
| 借贷平衡 | 借方总额必须严格等于贷方总额 | CRITICAL |
| 科目必填 | 分录科目不允许为空 | CRITICAL |
| 期间匹配 | 凭证期间必须在当前开放的会计期间内 | HIGH |
| 凭证断号 | 检测凭证编号是否连续 | MEDIUM |
| 辅助核算完整 | 科目挂接了辅助核算（部门/客户/项目）但分录未填 | MEDIUM |
| 预算额度控制 | 发生额超预算时预警或阻断 | MEDIUM |

**1.2 异常检测**

通过 AI 模型扫描已提交的凭证，标记异常风险：

| 检测项 | 说明 | 默认严重度 |
|:---|:---|:---:|
| 借贷不平衡 | 借方总额≠贷方总额 | CRITICAL |
| 金额异常 | 单笔分录金额 > 1,000,000 元 | MEDIUM |
| 摘要可疑 | 含"补亏/退回/调整/调账/暂估"等关键词 | LOW |
| 科目串户 | 典型科目搭配违反常规（如借固定资产/贷应付账款但应为银行存款）| MEDIUM |
| 期间错误 | 凭证期间与当前开放期间不符 | HIGH |
| 重复凭证 | 与历史凭证金额+摘要+科目高度相似 | MEDIUM |
| 新供应商大额 | 首次合作供应商且金额 > 500,000 元 | MEDIUM |

**1.3 交互设计**

- 凭证详情页顶部显示风险标签（红色=CRITICAL / 黄色=HIGH / 蓝色=MEDIUM / 灰色=LOW）
- 风险标签点击可展开查看详细检测说明
- 审核工作台支持按风险等级排序筛选
- CRITICAL 级别异常可配置为阻断过账

### FR-AUDIT-02: 智能报销助手

**2.1 多票据识别**

- 员工拍照上传发票、行程单、定额票、打车票等
- 单次最多支持 10 张图片批量上传
- AI OCR 自动提取每张票据的结构化信息
- 自动校验发票真伪（对接电子税务局 API，可选）

**2.2 规则自动审核**

| 规则 | 说明 |
|:---|:-----|
| 差旅标准 | 自动匹配出差申请单，检查住宿标准、交通标准是否超标 |
| 招待标准 | 检查招待费是否超过公司规定的单次限额及年度预算 |
| 发票重复 | 检查同一发票号是否已在系统中存在（跨月重复报销检测）|
| 费用归属 | 根据部门和费用类型判断是否在合理范围内 |

**2.3 审核流程前置**

- 不符合公司政策的报销单自动给出修改提示，退回员工补充
- 简单合规审核在系统层自动完成，财务只需处理异常单
- 审核通过后自动生成报销凭证

### t_ai_anomaly_tag

| 字段 | 类型 | 说明 |
|:---|:---|:-----|
| id | BIGINT PK | 主键 |
| biz_type | VARCHAR(32) | 业务类型（voucher/receipt）|
| biz_id | BIGINT | 业务 ID |
| anomaly_type | VARCHAR(32) | 异常类型 |
| severity | VARCHAR(16) | LOW/MEDIUM/HIGH/CRITICAL |
| description | TEXT | 异常描述 |
| ai_task_id | BIGINT | 关联 AI 任务 ID |
| resolved | BOOLEAN | 是否已解决 |
| resolved_by | BIGINT | 解决人 |
| resolved_at | TIMESTAMP | 解决时间 |
