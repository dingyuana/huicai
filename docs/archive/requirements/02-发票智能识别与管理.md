---

## 1. 业务概述

发票管理是企业财务的日常核心工作，涵盖销售发票（销项）、采购发票（进项）和费用发票三大类。传统模式下，会计需逐张录入发票信息，手动关联客户/供应商，处理红冲/作废等特殊场景，工作量大且容易出错。

本模块实现发票的批量导入、智能识别、客户/供应商自动匹配、红冲关联以及凭证自动生成，大幅减少人工录入工作量。

---

## 2. 发票类型与导入方式

| 发票类型 | 说明 | 支持的录入方式 |
|:---|:---|:---|
| **销售发票**（销项） | 企业开具给客户的发票，确立应收账款 | Excel 批量导入、手工录入、电子税务局文件导入 |
| **采购发票**（进项） | 供应商开具给企业的发票，确立应付账款 | Excel 批量导入、手工录入、OCR 识别 |
| **费用发票** | 员工报销或对公支付的费用类发票 | OCR 拍照识别、手工录入、PDF/OFD 批量导入 |

## 3. 功能需求

### FR-INV-01: 发票 Excel 批量导入

**3.1 导入流程**

```
上传 Excel 文件
  ↓
自动定位表头行（识别 ≥5 非空单元格的行）
  ↓
列名智能映射（两阶段匹配，同银行流水列名解析器）
  ↓
逐行解析，按发票号分组（groupByInvoiceNo），合并明细行
  ↓
发票号冲突检测（filterConflicts）
  ↓
客户/供应商自动匹配
  ↓
红冲发票关联处理
  ↓
批量写入数据库 → 返回导入结果摘要
```

### FR-INV-02: 客户/供应商自动匹配

**自动匹配流程：**

```
读取发票行中的购方/销方名称和税号
  ↓
阶段一：按税号精确匹配
  ├─ 匹配已有客户/供应商的 tax_number 字段
  └─ 匹配成功 → 直接关联客商 ID
  ↓
阶段二：按名称模糊匹配（税号匹配失败时执行）
  ├─ 使用 pg_trgm 计算名称相似度，阈值 ≥ 0.8
  ├─ 匹配成功 → 提示"疑似已有客商，是否关联？"
  └─ 匹配失败 → 进入阶段三
  ↓
阶段三：自动创建新客商
  ├─ 根据发票信息自动创建客户/供应商档案
  ├─ 填入名称、税号、地址等基本信息
  └─ 标记来源为"FROM_INVOICE_IMPORT"
```

### FR-INV-03: 红冲发票自动关联

| 需求 | 说明 |
|:---|:-----|
| FR-INV-03.1 | 导入红字发票时自动识别红冲标志（金额负值/状态列含"红冲"/备注含关键词）|
| FR-INV-03.2 | 双重提取原蓝字发票号：优先级1→SourceRedInvoiceNo 列，优先级2→Remark 字段正则提取 |
| FR-INV-03.3 | 正则模式：`被红冲蓝字(?:数电)?发票号码[：:]\s*(\d+)` |
| FR-INV-03.4 | 匹配到蓝字发票后将其状态标记为 `REVERSED`（已红冲）|
| FR-INV-03.5 | 红冲发票导入后标记蓝字发票的 `is_reversed=true` |
| FR-INV-03.6 | 提供 `PostImportFixRedBlueLinks` 修复脚本，用于事后批量修复存量数据 |

**红冲识别规则（优先级）：**

| 优先级 | 判断条件 | 分类结果 |
|:---:|:---|:---|
| 1 | 价税合计 < 0 或 金额 < 0 | 红字发票 |
| 2 | 状态列包含"红冲" | 红字发票 |
| 3 | 状态列包含"作废" | 作废发票 |
| 4 | 以上都不是 | 正常发票 |

### FR-INV-04: 发票 OCR 智能识别

**支持场景：** 员工拍照或扫描上传发票图片（手机拍照/扫描仪/截图）。

**4.1 OCR 识别流程**

```
用户上传发票图片 → 前端预览 → 发起 OCR 请求
  ↓
Java 创建 t_ai_task (taskType=OCR)
  ↓ RabbitMQ
Python OCR 服务处理（Tesseract/PaddleOCR）
  ↓
结构化提取：发票号码 / 金额 / 税额 / 开票日期 / 购销方信息
  ↓
AI 费用归类（基于商户名+商品名）
  ↓
结果回传到 Java → 更新前端 → 用户确认
```

**4.2 提取字段**

| 字段 | 说明 | 提取方式 |
|:---|:---|:---:|
| invoice_no | 发票号码 | OCR + 正则提取 |
| invoice_date | 开票日期 | OCR + 正则提取 |
| amount | 价税合计 | OCR + 正则提取 |
| tax_amount | 税额 | OCR + 正则提取 |
| vendor_name | 销方名称（费用发票场景关注）| OCR + 正则提取 |
| buyer_name | 购方名称 | OCR + 正则提取 |
| raw_text | 原始识别文本 | OCR 输出 |

**4.3 费用归类与科目推荐**

根据商户名称+商品名自动推荐费用类型：

| 商户/场景 | 推荐费用类型 | 置信度 | 推荐借方科目 |
|:---|:---|:---:|:---|
| 美团/大众点评/餐饮发票 | 业务招待费 | 95% | 6602.03 管理费用-业务招待费 |
| 中国石化/加油站 | 车辆费 | 92% | 6602.04 管理费用-车辆使用费 |
| 携程/飞猪/高铁票 | 差旅费 | 90% | 6602.05 管理费用-差旅费 |
| 顺丰/EMS/快递 | 快递费/办公费 | 88% | 6602.07 管理费用-办公费 |
| 京东/天猫办公用品 | 办公费 | 85% | 6602.07 管理费用-办公费 |
| 电信/移动/联通 | 通讯费 | 90% | 6602.08 管理费用-通讯费 |
| 房屋租金/物业费 | 租赁费 | 85% | 6602.09 管理费用-租赁费 |

置信度低于 80% 时不自动推荐，直接要求用户手动选择。

| 销售发票（确认收入） | 1122 应收账款（价税合计）| 5001 主营业务收入（不含税）|
| | | 2221.01 应交税费-销项税 |
| 进项发票（采购入库） | 1403 原材料/库存商品 | 2202 应付账款（价税合计）|

状态流转：`发票已确认 → 自动生成凭证草稿 → 总账审核 → 过账`

## 4. 数据模型

### t_output_invoice（销项发票）

| 字段 | 类型 | 说明 |
|:---|:---|:-----|
| id | BIGINT PK | 主键 |
| invoice_no | VARCHAR(64) NOT NULL | 发票号码 |
| invoice_date | DATE | 开票日期 |
| period | VARCHAR(6) | 会计期间 |
| customer_id | BIGINT FK | 客户 ID |
| customer_name | VARCHAR(200) | 客户名称 |
| amount | NUMERIC(18,2) | 不含税金额 |
| tax_rate | NUMERIC(5,2) | 税率 |
| tax_amount | NUMERIC(18,2) | 税额 |
| total_amount | NUMERIC(18,2) | 价税合计 |
| invoice_type | VARCHAR(32) | 发票类型（专票/普票/全电）|
| status | VARCHAR(20) | 状态（draft/verified/partially_paid/paid/reversed）|
| is_return | BOOLEAN | 是否红冲发票 |
| source_red_invoice_no | VARCHAR(64) | 原蓝字发票号（红冲用）|
| remark | TEXT | 备注 |
| doc_id | BIGINT FK | 关联业务单据 ID |
| voucher_id | BIGINT FK | 关联凭证 ID |
| ocr_data | JSONB | OCR 识别原始数据 |

### t_input_invoice（进项发票）

与销项发票结构对称，增加 `supplier_id`、`certification_status`（认证状态）等字段。
