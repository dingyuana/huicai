## 1. AI 服务架构

### 1.1 通信机制

AI 模块为独立 Python 微服务，与 Java 主系统通过 RabbitMQ 异步通信：

```
┌─────────────────────┐         ┌──────────────────┐         ┌──────────────────────┐
│   Java 主系统       │         │    RabbitMQ       │         │   Python AI 服务     │
│                     │         │                  │         │                      │
│  AiTaskService ─────┼────────→│ task.queue ──────┼────────→│ TaskConsumer        │
│  (创建任务, 写入    │         │                  │         │  ┌───────────────┐  │
│   t_ai_task 表)    │         │                  │         │  │ OCR Handler   │  │
│                     │         │                  │         │  │ Match Handler │  │
│  AiResultListener ◄─┼─────────│ result.queue ◄───┼─────────│  │ Anomaly Hndlr │  │
│  (接收结果, 更新    │         │                  │         │  │ Embed Handler │  │
│   业务表)          │         │                  │         │  └───────────────┘  │
└─────────────────────┘         └──────────────────┘         └──────────────────────┘
```

### 1.2 任务生命周期

```
状态流转: PENDING → PROCESSING → COMPLETED / FAILED
                                     ↓
                             等待人工审核
                                     ↓
                          APPLIED / REJECTED
```

| 状态 | 说明 |
|:---|:-----|
| PENDING | 任务已创建，待 RabbitMQ 投递 |
| PROCESSING | AI 服务正在处理 |
| COMPLETED | AI 处理完成，结果已写入，待人工审核 |
| FAILED | AI 处理失败，查看错误信息后重试 |
| APPLIED | 人工审核通过，结果已应用到业务数据 |
| REJECTED | 人工驳回，AI 建议未被采纳 |

### 1.3 AI 服务组件

| 服务 | 技术栈 | 功能 | 部署要求 |
|:---|:---|:---|:---:|
| OCR 服务 | PaddleOCR / Tesseract + OpenCV | 发票/回单图片识别 | CPU 即可 |
| 文本嵌入服务 | text2vec-base-chinese / BGE | 生成摘要文本的向量 | CPU 即可 |
| 匹配服务 | Jaccard 相似度 + 向量余弦 | 银行对账、核销匹配 | CPU 即可 |
| 异常检测 | Isolation Forest / 规则引擎 | 识别凭证异常 | CPU 即可 |
| 预测服务 | Prophet / ARIMA | 收入/费用趋势预测 | CPU 即可 |
| 问答服务 | LangChain + LLM (API 或本地) | 财务制度问答、NL2SQL | 推荐 GPU |

### 1.4 三层分类架构

```
优先级:  规则引擎(高) > AI 语义(中) > 兜底启发式(低)
              ↓              ↓              ↓
           确定性高         灵活性强      100%有结果
           Java 本地       Python 微服务   Java 本地
```

- **规则引擎**（Java 本地）：银行手续费、利息、税费等高频确定性场景，毫秒级响应，不依赖 AI 服务
- **AI 语义**（Python 微服务）：陌生对手方、模糊摘要、费用类型推荐，结果需人工确认
- **兜底启发式**（Java 本地）：硬编码关键词分组，确保每笔流水有分类

## 2. 人工审核闭环

所有 AI 输出必须经过"建议→人工确认→生效"流程：

```
AI 输出结果
  ↓
写入相关表的 ai_* 字段（不影响业务字段）
  ↓
前端展示 AI 建议（彩色标签 + 置信度）
  ↓
用户审核
  ├─ 采纳 → 确认后写入业务字段，状态变更为已确认
  ├─ 驳回 → 不采纳，记录驳回原因
  └─ 修改 → 人工修正后写入，记录修改差异
  ↓
人工操作记录写入 t_ai_feedback_log
  ↓（后续）
用于模型训练，持续优化 AI 准确率
```

| 应用场景 | AI 输出 | 人工确认方式 |
|:---|:---|:---|
| 银行流水分类 | 分类建议 + 置信度 | 出纳工作台确认/重分类 |
| 发票客户匹配 | 推荐客户/供应商 | 导入预览时确认 |
| 费用科目推荐 | 推荐科目 + 置信度 | 报销单编辑时确认 |
| 核销推荐 | 推荐发票 + 匹配度 | 核销工作台确认 |
| 异常检测 | 风险标签 + 严重度 | 凭证审核时确认/忽略 |
| 凭证自动生成 | 草稿凭证 | 凭证审核工作台确认过账 |

## 3. AI 反馈学习机制

### 3.1 反馈日志

每次人工修正 AI 建议时，记录到 `t_ai_feedback_log`：

```json
{
  "bank_txn_id": 10086,
  "ai_suggested_action": "business_payment",
  "ai_confidence": 65,
  "ai_business_scene": "供应商付款",
  "human_action": "business_receipt",
  "human_modified_fields": {
    "classification": {"from": "business_payment", "to": "business_receipt"},
    "counterparty": {"from": null, "to": "北京华联商贸有限公司"}
  }
}
```

### 3.2 优化闭环

- 每日/每周汇总反馈数据
- 分析常见修正模式：哪些场景下 AI 经常出错
- 定期更新 AI 模型或补充规则
- 反馈日志可视化仪表板：准确率趋势、常见错误类型分布

## 4. 数据安全与合规

| 要求 | 说明 |
|:---|:-----|
| 存储加密 | 所有敏感财务数据在数据库中加密存储 |
| 传输加密 | API 通信使用 HTTPS，RabbitMQ 使用 TLS |
| AI 数据隔离 | AI 服务仅接收结构化业务数据，不暴露敏感字段 |
| 私有化部署 | AI 模型支持完全私有化，不依赖外部 API |
| 操作留痕 | 所有 AI 建议和人工修正记录均可审计追溯 |
| 权限控制 | AI 功能按角色开放，部分功能需财务经理授权 |

## 5. 非功能需求

| 编号 | 要求 |
|:---|:-----|
| NFR-AI-01 | 单次 AI 任务处理时长 < 5s（OCR 除外）|
| NFR-AI-02 | AI 服务支持水平扩展，多实例负载均衡 |
| NFR-AI-03 | AI 服务不可用时，财务核心功能仍可正常运行 |
| NFR-AI-04 | 规则引擎处理耗时 < 50ms/条 |
| NFR-AI-05 | 模型更新不中断在线服务（蓝绿部署）|
| NFR-AI-06 | AI 服务日志与业务日志分开存储，方便问题排查 |
