# 慧财财务 — 需求分析书 00：总览与架构

> 版本：V1.0 | 日期：2026-06-12
> 本文档为慧财财务系统完整需求分析的总纲，定义项目目标、总体架构、核心原则和三阶段演进路线。

---

## 1. 项目概述

### 1.1 项目名称

慧财财务（Huicai Financial）— 基于 Web 的企业智能财务核算系统。

### 1.2 项目背景

传统财务软件操作繁琐，会计日常需花费大量时间在银行流水整理、发票录入、凭证制单、月末对账核销等重复性工作。现有的财务系统在数据录入、分类匹配、审核分析等环节高度依赖人工，效率和准确性难以兼顾。

随着人工智能技术的成熟，通过 AI 实现财务流程自动化、风险预警和智能分析，已成为企业数字化转型的关键方向。本系统在传统财务软件架构之上，系统化引入 AI 能力，构建"智能识别→自动制单核销→智能审核分析→风险预测与知识赋能"的完整智能财务体系。

### 1.3 建设目标

| 维度 | 目标 |
|:---|:---|
| **效率** | 事务性处理时间降低 70%-80%，财务人员转向高价值分析工作 |
| **风险** | 实时合规检查与异常预警，降低错账、税务风险、坏账损失 |
| **决策** | 管理者获得更及时、精准的分析与预测，支撑经营决策 |
| **体验** | 报销、查询、对账等环节的智能交互，提升全员满意度 |

### 1.4 适用范围

本需求分析书适用于慧财财务系统的整体设计与开发，涵盖以下业务域：

- 系统管理与基础数据（科目、期间、权限、摘要库）
- 业务单据管理（银行流水、收付款单、费用报销单、发票）
- 财务核心（凭证管理、账簿、期末结账）
- 出纳管理（银行对账、日记账、票据管理）
- 往来管理（应收应付、核销、坏账）
- 税务管理（进销项、申报、税负分析）
- 固定资产管理
- 预算管理
- 报表中心与财务分析
- **AI 辅助模块**（识别、分类、推荐、审核、预测、问答）

## 2. 核心设计原则

| 原则 | 说明 |
|:---|:---|
| **人工最终确认** | 所有 AI 生成结果均为草稿，必须经人工审核确认方可过账 |
| **规则+AI 双层保障** | 高频确定性场景走规则引擎，模糊场景由 AI 语义补充，兜底机制确保 100% 有结果 |
| **持续学习优化** | 基于人工修正数据不断训练模型，越用越准 |
| **安全合规** | 财务数据严格隔离，敏感信息加密，操作全程留痕 |
| **凭证不可篡改** | 已审核/已记账凭证只能红冲，不能直接修改 |
| **全操作可追溯** | 所有关键操作记录审计日志，存储操作前后数据快照 |

### 3.1 技术栈

| 层级 | 技术选型 | 说明 |
|:---|:---------|:-----|
| 后端框架 | Spring Boot 3.x | 核心框架，微服务可选演进 |
| 安全 | Spring Security + JWT | 认证授权，按钮级权限 |
| ORM | MyBatis-Plus | 适配 PostgreSQL 高级特性 |
| 主数据库 | PostgreSQL 16 | pgvector + pg_trgm 扩展 |
| 缓存/锁 | Redis 7 | 序列号生成、分布式锁 |
| 消息队列 | RabbitMQ | AI 任务异步分发 |
| 文件存储 | MinIO | 凭证影像、发票扫描件 |
| AI 服务 | Python 3.11 + FastAPI | OCR、NLP、异常检测、LLM |
| 前端 | Vue 3 + Element Plus + ECharts | 管理后台、数据可视化 |
| 接口文档 | Knife4j (Swagger) | 自动生成 API 文档 |

### 3.2 AI 服务架构

AI 模块为独立 Python 微服务，通过 RabbitMQ 与 Java 主系统异步通信：

```
Java 主系统                      RabbitMQ                    Python AI 服务
──────────                      ────────                    ──────────────
AiTaskService ──创建任务──→   huicai.ai.task.queue  ──消费──→  TaskConsumer
                               ↑                                  │
AiResultListener ←──结果回传── huicai.ai.result.queue ←──发布──  四种 Handler
                                                                  (OCR/MATCH/ANOMALY/EMBEDDING)
```

所有 AI 结果需人工审核方可生效：`建议 → 人工确认 → 生效`。

## 4. 三阶段演进路线

| 阶段 | 时间规划 | 核心主题 | 关键交付 |
|:---|:---------|:---------|:---------|
| **第一阶段** | 1-3 个月 | 智能识别与自动制单核销 | 银行流水/发票自动识别、分类、生成草稿凭证、自动核销建议、人工复核界面 |
| **第二阶段** | 4-8 个月 | 智能审核分析与税务管理 | 凭证审核、异常检测、NL2SQL 分析、智能报销、税务管理、合同应付管理 |
| **第三阶段** | 9-14 个月 | 智能预测与知识赋能 | 现金流预测、信用预警、月末自动检查、跨系统对账、档案检索、知识问答、预算管理 |

### 4.1 第一阶段：智能识别与自动制单核销（基础智能化）

解决财务最耗时的数据录入与匹配工作，实现银行流水、发票的自动识别，以及凭证和核销草稿的自动生成。

**核心模块：**
- 银行流水智能处理（导入、列名映射、意图分类、自动生成单据/凭证）
- 发票全形态智能识别（Excel 导入、OCR 识别、客户/供应商自动匹配、红冲关联）
- 科目智能推荐与凭证自动生成（规则+AI 双引擎、辅助核算自动填充）
- 自动核销（多级匹配策略、核销工作台、未匹配处理）

**阶段成果：** 凭证制单效率提升 70%，发票处理时间缩短 80%，月末核销工作量减少 60%。

### 4.2 第二阶段：智能审核分析与税务管理（深度智能化）

从"自动制单"延伸到"风险管控与决策支持"。

**核心模块：**
- 智能凭证审核（合规性检查、异常检测、重复入账拦截）
- 智能报销助手（多票据 OCR、规则自动审核）
- 自然语言财务分析（NL2SQL 查询、月度经营分析自动生成）
- 智能税务管理（税负测算、进项认证优化、税务风险扫描、出口退税底稿）
- 合同应付智能管理（条款提取、应付计划生成）

**阶段成果：** 会计审核效率提升 50%，财务分析报告准备时间由数天压缩至小时级，税务风险主动发现率提升 80%。

### 4.3 第三阶段：智能预测与知识赋能（全面智能化）

打造主动式、预见型财务系统。

**核心模块：**
- 现金流预测与资金预警
- 客户信用与坏账预警
- 自动月末结账检查
- 跨系统智能对账
- 电子会计档案智能检索与审计支持
- 财务知识问答与 Copilot
- 预算智能编制与执行监控

**阶段成果：** 月结时间缩短 50% 以上，现金流预测准确率可达 85%+，对账自动化覆盖 90% 常规差异，财务整体人效提升 3-5 倍。

## 6. 总体数据模型

系统数据库基于 PostgreSQL 16，核心表命名前缀 `t_`，采用 `snake_case` 命名规范。

| 表类别 | 说明 |
|:---|:-----|
| `t_subject` | 会计科目（树形结构，支持辅助核算）|
| `t_voucher` / `t_voucher_entry` | 凭证主表 / 分录（状态机：草稿→已提交→已审核→已记账）|
| `t_subject_balance` | 科目余额快照（按期间）|
| `t_business_doc` / `t_business_doc_entry` | 业务单据主表 / 分录（收款/付款/报销/转账）|
| `t_bank_statement` | 银行对账单（导入流水，含 AI 分类字段）|
| `t_classification_rule` | 分类规则表（智能分类引擎）|
| `t_ai_task` | AI 任务表（RabbitMQ 异步任务追踪）|
| `t_ai_anomaly_tag` | 异常标记表（凭证/流水风险记录）|
| `t_ai_feedback_log` | AI 反馈日志（人工修正记录，用于模型学习）|
| `t_voucher_template` | 凭证模板（按单据类型配置科目映射）|
| `t_output_invoice` / `t_input_invoice` | 销项 / 进项发票 |
| `t_customer` / `t_vendor` | 客户 / 供应商档案 |
| `t_receivable` / `t_payable` | 应收 / 应付明细 |
| `t_reconciliation_log` | 核销记录 |
| `t_budget` / `t_budget_entry` | 预算主表 / 预算明细 |
| `t_report_template` | 报表模板 |
| `t_attachment` | 通用附件（文件存 MinIO）|
| `t_audit_log` | 审计日志（AOP 记录操作前后快照）|

> **详细数据库设计**见各子模块需求分析。

## 7. 保障机制

| 机制 | 说明 |
|:---|:-----|
| **数据安全** | 所有敏感数据存储加密，AI 调用支持私有化部署 |
| **人工复核** | 各阶段 AI 输出均需确认，关键操作二次验证 |
| **持续优化** | 建立标注-训练-反馈闭环，模型定期迭代 |
| **平滑升级** | 功能模块化，不影响现有财务系统核心流程 |
| **审计追溯** | 所有 AI 建议和人工修正记录均可追溯 |
