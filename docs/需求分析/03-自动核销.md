# 慧财财务 — 需求分析书 03：智能辅助核销

> 版本：V1.0 | 日期：2026-06-12 | 归属：第一阶段
> 对应项目说明书：§4.7 往来管理、§4.12.3 智能辅助核销

---

## 1. 业务概述

核销是连接业务流（发票）与资金流（收/付款单、银行流水）的关键环节。传统模式下，会计需逐一核对发票与收付款记录，手动匹配金额、客户/供应商信息，工作量大且容易遗漏。

本模块实现多层次的智能辅助核销，基于金额、摘要相似度、对方名称等维度自动推荐匹配方案，大幅降低人工匹配工作量。

---

## 2. 业务流程

```
业务收款/付款发生（来自银行流水自动创建 或 手工录入）
  ↓
系统自动推荐待核销发票
  ├─ 按客户/供应商筛选
  ├─ 按金额匹配（精确/容差/部分）
  └─ 按摘要相似度排序
  ↓
前端展示推荐结果（匹配度评分 + 分级高亮）
  ↓
出纳确认核销方案
  ├─ 完全匹配 → 一键核销
  ├─ 部分匹配 → 输入本次核销金额 → 分批核销
  └─ 多单匹配 → 勾选多张发票 → 批量核销
  ↓
执行核销 → 更新发票状态（部分核销/已核销）
  ↓
自动生成核销凭证（如果需要）
```

---

## 3. 功能需求

### FR-RECON-01: 收款核销推荐

创建或确认收款单时，系统自动推荐待核销的销售发票：

```
选择客户 → 系统自动查询该客户所有已确认/部分核销的销售发票
  ↓
执行匹配度评分算法:
  匹配度 = 金额一致(0.4) + 摘要相似度(0.4) + 对方户名匹配(0.2)

金额一致(0.4):
  ├─ 收款金额 = 发票未核销余额 → +0.4
  └─ 金额差异在容差范围内 → +0.3

摘要相似度(0.4):
  └─ 收款单摘要与发票摘要的 Jaccard 相似度 × 0.4
  └─ 中文二元分词 + 英文单词切分

对方户名匹配(0.2):
  ├─ 收款单对方户名 = 发票客户名称 → +0.2
  └─ 模糊匹配 ≥ 80% → +0.1
```

| 匹配度 | 颜色 | 操作建议 |
|:---:|:---:|:---|
| ≥0.95 | 🟢 绿色 | 一键核销 |
| 0.7-0.94 | 🟡 黄色 | 核对后核销 |
| <0.7 | ⚪ 灰色 | 不出现在推荐列表 |

### FR-RECON-02: 付款核销推荐

逻辑与收款核销对称，供应商替换客户，采购发票替换销售发票：

- 按供应商筛选未核销采购发票
- 金额一致 + 摘要相似度 + 对方户名匹配
- 匹配度 ≥ 0.7 的候选发票展示供会计确认

### FR-RECON-03: 银行流水自动匹配回款核销

对于银行流水分类为 `business_receipt` 或 `business_payment` 的流水，系统自动尝试直接匹配未核销发票：

```
银行流水 → 分类为 business_receipt/business_payment
  ↓
自动创建收款单/付款单
  ↓
按对方户名匹配客户/供应商档案
  ↓
按客户/供应商查询所有已确认/部分核销的发票
  ↓
执行核销匹配算法（同 FR-RECON-01）
  ↓
匹配度 ≥ 0.7 的候选发票展示给出纳
  ↓
出纳确认 → 执行核销 → 更新发票状态 → 自动生成收款/付款凭证
```

### FR-RECON-04: 核销匹配策略

| 策略 | 说明 | 示例 |
|:---|:---|:---|
| **精确匹配** | 流水/收付款金额 = 发票未核销余额，摘要含发票号 | 30,000 元回款匹配 30,000 元发票 |
| **容差匹配** | 金额差额在设置的容差阈值内（如 ±5 元，含手续费） | 银行扣了手续费后实收 29,995 匹配 30,000 元发票 |
| **部分核销** | 本次只核销部分金额，剩余继续挂账 | 回款 20,000 元，发票金额 50,000 元，部分核销 20,000 |
| **多对一核销** | 多笔流水/收付款共同对应一笔发票 | 两次回款 15,000+15,000=30,000 核销一张发票 |
| **一对多核销** | 一笔流水/收付款核销多张发票 | 一笔回款 50,000 核销三张发票（10,000+20,000+20,000）|
| **溢收款/预收款** | 多出金额自动转为预收款 | 回款 35,000 但发票只有 30,000，剩余 5,000 记为预收款 |
| **尾差处理** | 小额尾差计入财务费用 | 少收 0.50 元计入财务费用-尾差 |

### FR-RECON-05: 核销工作台

| 需求 | 说明 |
|:---|:-----|
| FR-RECON-05.1 | 统一核销工作台，展示所有待核销的收/付款单及推荐核销方案 |
| FR-RECON-05.2 | 每笔推荐展示：发票号/日期/原金额/未核销余额/匹配度评分 |
| FR-RECON-05.3 | 完全匹配项高亮绿色，可直接一键核销 |
| FR-RECON-05.4 | 支持勾选多笔高置信度推荐，批量执行核销 |
| FR-RECON-05.5 | 支持手工调整：修改核销金额、更换匹配发票、取消匹配 |
| FR-RECON-05.6 | 部分核销时显示：已核销金额 / 未核销金额 |
| FR-RECON-05.7 | 核销完成后自动更新发票状态为部分核销/已核销 |
| FR-RECON-05.8 | 核销操作记录审计日志 |

### FR-RECON-06: 核销记录追溯

| 需求 | 说明 |
|:---|:-----|
| FR-RECON-06.1 | 发票详情页设"核销记录"选项卡，以时间轴展示所有核销操作 |
| FR-RECON-06.2 | 每条记录包含：关联收/付款单号（可穿透）、核销金额、核销日期、操作人 |
| FR-RECON-06.3 | 费用发票展示"凭证记录"选项卡，关联生成的凭证号和报销单号 |
| FR-RECON-06.4 | 从收/付款单可穿透至对应的银行流水，形成完整资金链路 |

## 4. 数据模型

### t_reconciliation_log

| 字段 | 类型 | 说明 |
|:---|:---|:-----|
| id | BIGINT PK | 主键 |
| tenant_id | BIGINT NOT NULL | 租户 ID |
| source_doc_type | VARCHAR(32) | 来源单据类型（receipt/payment/bank_txn）|
| source_doc_id | BIGINT | 来源单据 ID |
| target_doc_type | VARCHAR(32) | 目标单据类型（invoice/ar/ap）|
| target_doc_id | BIGINT | 目标单据 ID |
| allocated_amount | NUMERIC(18,2) | 核销金额 |
| discount_amount | NUMERIC(18,2) | 现金折扣金额（如有）|
| match_score | NUMERIC(5,2) | 匹配度评分 |
| match_method | VARCHAR(20) | AUTO / MANUAL |
| status | VARCHAR(20) | PENDING / CONFIRMED / CANCELLED |
| created_by | BIGINT | 操作人 |
| created_at | TIMESTAMP | 创建时间 |
