## 2. 技术栈

### 2.1 实际使用

| 技术 | 版本 | 用途 | 选型理由 |
|------|------|------|---------|
| Spring Boot | 3.x | 后端框架 | LTS版本，支持虚拟线程 |
| MyBatis-Plus | 3.5.x | ORM | 多租户插件、分页插件 |
| PostgreSQL | 16 | OLTP + pgvector | 原生JSONB，强一致性，向量检索 |
| Redis | 7 | 缓存/分布式锁 | 凭证号生成、热点缓存 |
| RabbitMQ | 3.x | AI 异步任务 | 延迟队列、削峰 |
| MinIO | latest | 对象存储 | 发票附件、电子文件 |
| FastAPI | 0.110.x | AI 服务 | ASGI异步，自动OpenAPI |
| Vue 3 + Element Plus | 3.x | 前端 | 组合式API，企业级组件 |
| ECharts | latest | 可视化 | 财务图表、桑基图 |
| Apache POI | latest | Excel 导入导出 | 科目/客商导入、报表导出 |
| Flyway | latest | DB迁移 | 版本化数据库变更管理 |

### 2.2 明确排除的技术

| 技术 | 排除理由 |
|------|---------|
| 微服务/K8s/Nacos | 单体部署，运维成本最低 |
| Seata | 单体部署不需要分布式事务 |
| Kafka | RabbitMQ已足够 |
| ClickHouse | 当前数据量无需OLAP |
| Milvus | pgvector已够用 |
| Drools | 规则用代码实现更可控 |
| 其他RPC框架 | 无需跨服务调用 |

## 4. 关键设计决策

### 4.1 红冲机制
已审核/已过账凭证不可修改，只能通过反向单据修正。支持前向级联（发票/单据同步 REVERSED）和反向级联（凭证红冲回写源单据）。

### 4.2 核销架构
```
银行流水 → B类路由 → 收款单/付款单(DRAFT) → 核销工作台（唯一入口）→ 核销单 → 凭证
```
t_receivable/t_payable 已删除，统一使用 t_business_doc 表。

### 4.3 编号关联体系
所有核心实体通过编号双向关联，支持 6 种实体类型全链路追溯（凭证→发票→业务单据→银行流水→核销单→预付款）。

### 4.4 以票定账流程
```
发票导入(PENDING_CONFIRM) → 人工审核(PENDING_REVIEW) → 审核通过(CONFIRMED)
  → 自动生成业务单(DRAFT) + 应收/应付单 → 生成凭证(DRAFT)
```
审核通过后才生成下游业务单和凭证，不在导入时自动创建。

### 4.5 预算控制
事前控制：报销提交时实时校验预算余额，预占预算，驳回时释放。三级控制策略：WARN / APPROVE_REQUIRED / BLOCK。

### 4.6 Entity-DB 一致性保障
- 所有 `@TableId(type = IdType.AUTO)` 必须对应 DB `GENERATED ALWAYS AS IDENTITY`
- SchemaValidator 启动时检查 Entity 与 DB schema 一致性
- CI 脚本 `check-identity-consistency.mjs` 在构建前扫描检测
- V92/V93 migration 修复了全部缺失 IDENTITY 的表

### 4.7 API 路径规范
- 基础路径：`/api/{base|sme}/{module}/v1/{resource}`
- 前端构建时自动校验所有 API 路径前缀合规性
- nginx 配置 Cache-Control 防止浏览器缓存旧 JS

### 5.2 命名规范

- 表名：`t_` 前缀，小写蛇形
- 主键：`id BIGINT GENERATED ALWAYS AS IDENTITY`
- 审计字段：`created_by`, `created_at`, `updated_by`, `updated_at`, `deleted`
- 版本控制：`version` BIGINT（乐观锁）
- 编号字段：`xxx_no` VARCHAR（业务编号冗余）
- 关联字段：`xxx_id` BIGINT（外键）
- 金额字段：`NUMERIC(18,2)`，Java 用 BigDecimal
- 税率：存储百分比整数（13=13%）
- 状态字段：`status` VARCHAR(32)
- 扩展数据：`JSONB` 列（OCR结果、AI负载、辅助核算）

## 6. API 设计规范

### 6.1 通用规范

- 基础路径：`/api/v1/`
- 资源命名：全小写、中划线分隔（kebab-case），复数名词
- 响应格式：统一 `{ code, msg, data }`
- 分页响应：`{ records, total, current, size }`
- 错误处理：无路由返回 404，业务异常使用 `BusinessException`

### 6.2 错误码字典

| 段 | 业务域 | 示例 |
|----|--------|------|
| 20000-20099 | 系统级 | 20001=参数校验失败, 20002=未授权 |
| 20100-20199 | 业财底座 | 20101=借贷不平衡, 20103=期间已锁定 |
| 20200-20299 | 税务发票 | 20201=发票验真失败 |
| 20300-20399 | 资金核销 | 20301=核销金额超出余额 |
| 20400-20499 | AI 层 | 20401=置信度过低 |
