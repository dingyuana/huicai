# 慧财财务系统 AI 架构演进设计文档

> **编号**：HUICAI-ARC-001
> **版本**：V1.0 | **修改日期**：2026-07-07 | **修改人**：Hermes | **修改内容**：添加编号头部
### 1.1 核心原则
- **先验证价值，再优化架构**：不盲目引入微服务、K8s 等复杂组件
- **保留现有资产**：充分利用已实现的核心业务流程，不重写
- **渐进式演进**：分 3 个阶段，每阶段有明确的业务目标和验收标准
- **分层解耦**：AI 编排层独立部署，与现有 Spring Boot 单体通过 API 通信

### 1.2 总体路线图
- **阶段一**（MVP 验证）：接入 AI 编排层，验证科目映射、异常检测、流水分类能力
- **阶段二**（业财智能打通）：完善 8 大智能体，引入 AI 辅助报告分析
- **阶段三**（持续优化）：按需优化架构，不引入微服务/K8s 等复杂组件

## 三、 AI 编排层设计

### 3.1 核心组件
- **编排引擎**：LangGraph（利用 DAG 状态机特性）
- **AI 开发框架**：LangChain
- **RAG 知识引擎**：pgvector（PostgreSQL 扩展）
- **Web 框架**：FastAPI
- **流式输出**：SSE（Server-Sent Events）

### 3.2 8 大智能体
| 智能体 | 职责 |
|-------|------|
| Invoice-Agent | 发票识别、分类、科目映射 |
| Voucher-Agent | 凭证智能生成、科目说明 |
| BankReconciliation-Agent | 银行流水自动分类、智能匹配 |
| BI-Agent | 自然语言问数、图表生成 |
| Tax-Agent | 税务政策咨询、风险检测 |
| Payroll-Agent | 薪资社保计算 |
| Expense-Agent | 费用报销智能审核 |
| Receivable-Agent | 应收应付分析、催收建议 |

### 3.3 LangGraph 状态图示例（凭证生成）
```
用户输入 → 解析上下文 → 调用科目映射工具 → 生成借贷分录 → 确认 → 完成
                              ↓
                         RAG检索政策
```

## 四、 数据库设计（RAG 扩展）

### 4.1 pgvector 向量表
```sql
-- 已在现有的 PostgreSQL 16 上执行
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE t_rag_document (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    content TEXT NOT NULL,
    embedding vector(1536) NOT NULL,
    metadata JSONB,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX ON t_rag_document USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);
```

## 六、 部署架构

### 6.1 Docker Compose 更新
在现有 `docker-compose.yml` 中新增 `ai-service`：
```yaml
ai-service:
  build: ./ai-service
  container_name: huicai-ai-service
  ports:
    - "8001:8001"
  environment:
    - AI_MODEL_ENDPOINT=...
    - PG_HOST=postgres
  depends_on:
    - postgres
  networks:
    - huicai-net
```

### 6.2 环境变量

## 七、 可观测性与治理

### 7.1 监控
- Prometheus + Grafana：监控 AI 接口延迟、Token 消耗、业务异常率
- OpenTelemetry：记录 Agent 的思考与调用链

### 7.2 安全
- Spring Security + JWT：保持现有认证体系
- AI 护栏：Prompt 注入拦截、敏感词过滤、输出合规校验

## 八、 风险与应对

| 风险 | 应对 |
|-----|------|
| 团队对 LangGraph/AI 不熟悉 | 先做技术预研，找一个小场景练手 |
| pgvector 性能不满足预期 | 后期考虑换 Milvus，但先从 pgvector 开始 |
| AI 效果不达标 | 先基于规则 + 少量 RAG，再逐步优化 Prompt 和 Skill |
| 过度设计诱惑 | 严格按阶段执行，没验证业务价值不做架构重构 |
