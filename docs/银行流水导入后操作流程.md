# 银行流水导入后操作流程

> 本文档描述银行流水 Excel 导入后，系统内部的完整流转链路。
> 从解析入库 → 智能分类 → 审核工作台 → 生成凭证/付款单 → 核销匹配 → 银企对账。

---

## 全链路概览

```text
Excel 导入
    │
    ▼
[智能分类] ──规则引擎 + 启发式兜底──→ 三分类
    │
    ├── 第一类 (A) ──→ 直接生成凭证草稿 ──→ 人工核准 → 过账
    │
    ├── 第二类 (B) ──→ 生成付款单/收款单草稿 ──→ 关联发票核销 → 生成凭证 → 核准 → 过账
    │
    └── C 类 ──→ 待处理工作台 ──→ 人工指定 A/B 类 → 继续上述流程
                                                              │
                                                              ▼
                                                       [银企对账]
                                                   5 维评分自动匹配
                                                   余额调节表
                                                   锁定 → 完成对账
```

## 阶段一：导入 (Import)

### API

```
POST /api/v1/bank-transactions/import?bank_account_id=xxx&auto_create_party=true
```

### 解析逻辑 (`BankTransactionService.ImportFromExcel`)

1. **Excel 解析** — 使用 `xuri/excelize` 读取首 Sheet
   - 自动跳过空行/标题行，寻找包含 ≥5 列非空单元格的**真实表头行**
2. **列名智能匹配** — 支持中英文双模式：
   - 日期: `date / transaction date / 交易日期 / 记账日期 / 发生日期 / 日期`
   - 摘要: `description / 摘要 / 交易描述 / 备注 / 用途 / 附言`
   - 收入: `income / 收入金额 / 贷方金额 / credit`
   - 支出: `expense / 支出金额 / 借方金额 / debit`
   - 金额: `amount / 金额 / 发生金额 / 交易金额`
   - 对方: `付款人名称 / 收款人名称 / 对方户名 / counterparty`
   - 流水号: `voucher no / reference / 流水号 / 凭证号 / 交易流水号`
3. **数据校验** — 每行逐字段检查
   - 日期无法解析 → 失败
   - 摘要为空 → 失败
   - 金额为 0 → 失败
4. **对方自动建档 (可选)** — `auto_create_party=true`
   - 当对方名称为空时，从摘要中用正则提取公司名（`XXX有限公司`/`XXX税务局` 等）
   - 自动创建到客商档案，标记 `auto_created_parties` 数量
5. **重复检测** — 入库时按 `(tenant_id, bank_account_id, txn_date, description, amount)` 去重

### 导入后状态

每条流水初始状态设为 **`classified`**（已分类），等待审核工作台处理。

### 返回结果

```json
{
  "total_rows": 100,
  "success_count": 95,
  "failed_count": 5,
  "failed_rows": [3, 8, 12],
  "failed_reasons": [
    {"row": 3, "reason": "日期格式无法解析"},
    {"row": 8, "reason": "摘要为空"},
    {"row": 12, "reason": "金额为空"}
  ],
  "auto_created_parties": 2,
  "hint": "导入成功。所有流水进入待确认状态，请在出纳工作台进行审核确认后生成凭证或单据"
}
```

## 阶段二：智能分类 (Classification)

### 1. 规则引擎匹配 (`ClassificationRuleService.MatchTransaction`)

基于用户配置的分类规则，按 `(摘要关键词, 对方名称, 收支方向)` 匹配。

### 2. 启发式兜底 (`fallbackClassify`)

当规则引擎未匹配时，使用硬编码关键词：

| 分类 | 触发条件 |
|------|---------|
| `bank_fee` | 摘要含"手续费/服务费/账户管理费/年费/短信费" 等；或金额 < 50 元的支出 |
| `interest_income` | 摘要含"利息/结息/派息" |
| `insurance_fee` | 摘要含"保险/保费/投保" 等 |
| `tax_payment` | 摘要含"税款/税金/扣税/增值税/所得税" 等 |
| `social_security` | 需规则引擎 |
| `internal_transfer` | 摘要含"转账/划转/调拨/转存/转入/转出" |
| `business_receipt` | 收入方向，无其他关键词匹配 |
| `business_payment` | 支出方向，无其他关键词匹配 |

### 3. 三分流路由 (`classifyType`)

```go
func classifyType(classification string) string {
    switch classification {
    case "bank_fee", "interest_income", "tax_payment",
         "social_security", "insurance_fee":
        return "第一类"    // A类 → 直接制证
    case "business_receipt", "business_payment",
         "pay", "receive", "expense", "internal_transfer":
        return "第二类"    // B类 → 中转付款单
    default:
        return "C"        // C类 → 人工处理
    }
}
```

## 阶段三：审核工作台 (Review Workflow)

### 状态枚举

| 状态 | 含义 |
|------|------|
| `pending` | 待处理（初始状态） |
| `classified` | 已分类，等待审核提交 |
| `voucher_generated` | 凭证草稿已生成（待财务核准） |
| `payment_created` | 付款单草稿已生成（待业务审核） |
| `manual_pending` | C 类待人工处理 |
| `approved` | 已核准 |

### API

```
GET  /api/v1/bank-transactions/review-list?status=classified&page=1&page_size=50
GET  /api/v1/bank-transactions/review-stats
POST /api/v1/bank-transactions/preview-draft/:id
POST /api/v1/bank-transactions/submit-review
POST /api/v1/bank-transactions/reject-manual
POST /api/v1/bank-transactions/:id/process-manual
```

### 审核提交流程 (`SubmitReview`)

1. 选择多条 classified 状态的流水
2. 系统按分类路由：
   - **A类** → 调用 `AutoGenerationService.autoGenerate`（内部走 `generateVoucherDirect`）生成凭证草稿
   - **B类** → 调用 `AutoGenerationService.autoGenerate`（内部走 `generateDocThenVoucher`）生成单据 + 凭证 + 自动核销
3. 事务性提交：全部成功或全部回滚
4. 更新状态为 `voucher_generated` / `payment_created`

### C 类手工处理 (`ProcessManual`)

- 人工在待处理工作台查看无法自动分类的流水
- 选择指定为 "第一类"（直接制证）或 "第二类"（中转付款单）
- 若选第二类，还需指定 `payment_type` = `pay`（付款）或 `receive`（收款）

### 预览凭证 (`PreviewDraft`)

在提交前预览将要生成的凭证内容，A/B 类可预览，C 类无预览。

## 阶段四：凭证生成 (Voucher Generation)

### 科目映射 (`GenerateFromBankTxn`)

| 分类 | 借方科目 | 贷方科目 | 说明 |
|------|---------|---------|------|
| `bank_fee` | 银行存款（清算科目） | 5602 财务费用 | 银行手续费 |
| `interest_income` | 5602 财务费用（红字/贷方） | 银行存款 | 利息收入 |
| `tax_payment` | 2221 应交税费 | 银行存款 | 缴税 |
| `social_security` | 2211 应付职工薪酬 | 银行存款 | 社保缴费 |
| `insurance_fee` | 5601 管理费用 | 银行存款 | 保险费用 |
| `business_receipt` | 银行存款 | 1122 应收账款 | 收款 |
| `business_payment` | 2202 应付账款 | 银行存款 | 付款 |

- 凭证以 **草稿状态 (docstatus=0)** 创建，等待人工核准（docstatus=1）→ 过账（docstatus=2）
- 入账日期使用当前系统时间（`time.Now()`），而非银行流水日期

### 凭证模板

凭证号由 `VoucherTemplateService.GenerateVoucherNumber` 自动生成（基于模板规则）。

## 阶段五：核销匹配 (Reconciliation)

### 核销对象

- **来源**: 银行流水 (bank_txn, source_type=`bank_txn`) 或 付款单 (payment_entry)
- **目标**: 应收单 (t_receivable, target_doc_type=`INVOICE_OUT`) / 应付单 (t_payable, target_doc_type=`INVOICE_IN`)

### 5 级自动匹配 (`ReconciliationService.Reconcile`）

| 级别 | 策略 | 说明 |
|------|------|------|
| L1 | 引用号精确匹配 | 流水的 reference_no 包含发票 ID |
| L2 | 发票号匹配 | 流水摘要中包含发票号码 |
| L3 | 客商 + 金额 + 日期 | 对方名称一致 + 金额相等 + 日期 ±3 天 |
| L4 | 金额精确 | 仅金额相等，不要求对方名称 |
| L5 | 容差匹配 | 金额差异 ≤ 容差百分比（默认 10%）|

### 核销状态流转

核销日志表 `t_reconciliation_log` 的状态流转：

```text
自动匹配 (P10-4 自动核销调 execute)
    │
    ├── execute() ──→ CONFIRMED（已确认，待审批执行）──→ 人工审批 → executed
    │                                                      │
    └── 人工匹配 ──→ CONFIRMED ──→ 审批执行 → executed
                                                           └── 冲销反转 → reversed
```

### 审批执行操作 (`ApprovePairs`)

事务性操作：
1. 插入 `payment_allocations` 记录
2. 更新发票 `paid_amount`, `outstanding_amount`, `status`
3. 标记银行流水 `matched = true`
4. 更新核销对状态为 `executed`

### 预检查 (`PreCheck`)

核销前检查 5 项：
- 收款单是否有效（金额不为零、未生成凭证）
- 发票是否有效（未红冲、有未核销金额）
- 客商一致性（双方名称是否匹配）
- 金额匹配（付款金额是否充足）
- 期间检查（发票所属期间是否正常）

## 阶段六：银企对账 (Bank Reconciliation)

### 对账主体

- **银行流水** (bank_transactions) vs **总账分录** (gl_entries)
- 按银行账户 + 会计期间执行

### 5 维评分匹配 (`CalculateMatchScore`)

| 维度 | 满分 | 说明 |
|------|------|------|
| 金额匹配 | 50 | 完全一致=50，差异 ≤1% 按比例衰减，≤5% 最低 30 分 |
| 日期匹配 | 20 | 同天=20，±1 天按比例衰减，>3 天=0 |
| 名称匹配 | 15 | 编辑距离相似度 ≥90%=15，≥80%=10，≥70%=5 |
| 描述匹配 | 10 | 关键词（货款/采购/付款/收款等）命中数 |
| 参考号匹配 | 5 | 银行流水参考号与凭证号匹配 |

### 评分结果路由

| 总分 | 路由 |
|------|------|
| ≥85 | 自动匹配 (`IsAutoMatched`) — 直接标记，无需人工 |
| 60-85 | 待确认 (`NeedConfirm`) — 人工审核确认 |
| <60 | 未达账项 — 进入四方向分类 |

### 四方向未达账项

| 方向 | 含义 |
|------|------|
| `bank_receipt_not_in_gl` | 银行已收，企业未收 |
| `bank_payment_not_in_gl` | 银行已付，企业未付 |
| `gl_receipt_not_in_bank` | 企业已收，银行未收 |
| `gl_payment_not_in_bank` | 企业已付，银行未付 |

### 余额调节表

```text
银行对账单余额
    + 银行已收企业未收
    - 银行已付企业未付
    = 调整后余额
        vs
企业账面余额
    + 企业已收银行未收
    - 企业已付银行未付
    = 调整后余额
```

两者调整后余额应相等。

### 对账锁定

- 同一期间只能一个用户操作（`LockReconciliation` / `UnlockReconciliation`）
- 对账完成后 `MarkAsReconciled` → 期间锁定

---

## 阶段七：余额检查 (Balance Check)

`BankReconciliationService.BalanceCheck` 按租户检查所有银行账户的余额一致性：

```text
期初余额 + 净变化 (∑收入 - ∑支出) = 预期余额
预期余额 vs 当前存储余额 → 差异 = 0 则一致
```

用于日常对账前的健康检查。

## 关键数据模型

### `bank_transactions` 表关键字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `status` | `*string` | `pending` / `classified` / `voucher_generated` / `payment_created` / `manual_pending` |
| `classification` | `*string` | 智能分类结果 |
| `matched` | `bool` | 是否已被核销匹配 |
| `confirmed` | `bool` | 是否已人工确认 |
| `matched_gl_entry_id` | `*uuid` | 关联的凭证（总账分录）ID |
| `matched_payment_entry_id` | `*uuid` | 关联的付款单 ID |

### `reconciliation_pairs` 表

| 字段 | 说明 |
|------|------|
| `source_type` | `bank_txn` / `payment_entry` |
| `source_id` | 来源 ID |
| `target_type` | `invoice` / `ar_invoice` / `ap_invoice` |
| `target_id` | 目标发票 ID |
| `amount` | 核销金额 |
| `status` | `matched` / `confirmed` / `pending_review` / `executed` / `rejected` / `reversed` |
| `match_level` | `L1`-`L5` / `manual` / `auto` |

### `reconciliation_records` 表

| 字段 | 说明 |
|------|------|
| `bank_balance` | 银行对账单余额 |
| `book_balance` | 企业账面余额 |
| `adjusted_balance` | 调整后余额 |
| `bank_only_total` | 银行已收/付企业未记账合计 |
| `book_only_total` | 企业已收/付银行未记账合计 |
| `status` | `in_progress` / `reconciled` |
| `locked` / `locked_by` | 对账锁定 |
