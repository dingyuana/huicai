# P41-T2.2 任务：发票→业务单据 手动生单（参考现有状态机设计）

> 状态：待审核 | 优先级：高 | 预计工时：1.5 人日

## 任务描述
发票审核通过（CONFIRMED）后，不自动生单。财务人员**手动点击**"生成业务单据"按钮，触发创建 DRAFT 业务单据。

## 关联 SPEC
docs/specs/P41-invoice-driven-finance.md §1.2

## 具体要求

### 1. 关键设计

#### 修改 confirm() 方法（重要）
当前 P34 的 confirm() 在审核通过后自动调用 createBusinessDocFromInvoice + generateVoucherFromInvoiceDirect。
**需要改为**：confirm() 只改状态（CONFIRMED），不自动创建任何单据/凭证。

#### 新增"生成业务单据"端点（手动触发）
- 销项发票：POST /api/v1/tax/invoice/{id}/generate-doc
  - docType = "INVOICE_OUT"
  - status = "DRAFT"
- 进项发票：POST /api/v1/tax/invoice/{id}/generate-doc
  - docType = "INVOICE_IN"  
  - status = "DRAFT"

#### 业务单据状态流转（参考现有设计）
```
DRAFT → 人工提交审核 → SUBMITTED → 人工审核 → AUDITED
  ↕
  VOIDED
```

### 2. 修改文件
| 文件 | 修改内容 |
|------|----------|
| OutputInvoiceStateMachineServiceImpl.java | confirm() 去掉自动生单逻辑，只改状态 |
| TaxController.java | 新增 generateDoc 端点 |
| TaxServiceImpl.java | 新增 generateDoc 方法，创建 BusinessDoc DRAFT |

### 3. 验收标准
- confirm() 只改状态，不创建单据+凭证
- 手动调用 generate-doc 端点后创建 DRAFT 业务单据
- 业务单据回写发票的 doc_id/doc_no 字段
- 业务单据保持 DRAFT 不变，不自动审核

## 不要做
- 不要自动审核业务单据（保持 DRAFT）
- 不要自动生成凭证
- 不要修改凭证生成逻辑
